# Uagray 设计生成

## 唯一依据

此 Skill 随 Uagray 仓库维护。仓库根目录为本文件所在目录的 `../../..`。先读取 [设计参考规范](../../../docs/design-system.md)，按当前任务查对应章节；属性与状态查 [API 名单](../../../docs/api-contract.md)，资源接入查 [Token 映射](../../../docs/tokens.md)。不复制一套规范到 Skill，不从 references/history 或旧截图恢复已撤销规则。

如果 Skill 被复制到其他位置，先定位包含上述文档与 src/ui/index.ts 的 Uagray 仓库；找不到时说明缺失依据，不凭记忆生成规范。宿主页面可位于其他项目，Uagray 规范与脚本仍从库仓库读取。

## 从需求到实现

- 先区分是在改基础组件、组合还是宿主页面。说明必要内容、真实状态、操作和宿主宽度，再选择环境、边界与排列；不要从“套一张卡片”开始。
- 检查 src/ui/index.ts、相关组件源码及当前 Props，优先复用现有控件。页面生成只实现用户要求的任务；不得把页面辅助开关、模拟反馈、路由或业务文案固化到库组件。
- 复杂需求的意愿或外观决策不清楚时，提出具体方案再实施；已确认的规则直接落实。主规范中的待讨论动效不因任务要求“优化”便自动成为新参数或全局规则。
- 根据实际角色读取语义资源，按真实 inset 与边缘规划圆角，检查整个工具行的外高和可见留白。以名称、状态和内容建立识别，不用重复题注或模拟成功流水补布局。
- 保留原生属性、真实焦点与可访问名称；合成值回调、受控状态与实际交互 ref 遵从当前 API。用库现有组件组合编辑器，不临时换用另一套视觉控件。
- 动效复用共享配置；几何同时服务 CSS 与 Motion。渐隐、展开与局部测量以实际内容为依据，不强制所有文本拥有截断或展开入口。
- 修改库 API 时同步真正消费该属性的预览、元数据和生成用法；纯宿主排布不扩展库 API。维护已有本地改动，不执行任务未要求的发布、推送或删除。

## 完成检查

在 Uagray 根目录执行 `npm run check:design` 与类型检查，按改动选择相关交互测试。若修改检查器本身，再执行 `npm run test:design`。不要为一次局部样式调整自动运行全部打包、消费或浏览器验收。

脚本只验证已登记的源码契约。新组合需要在 scripts/check-design.mjs 中补充可静态计算的关系；不能因为脚本没发现问题就宣布新组件完整合规。光学留白、实际换行、色差和交互体验仍要按主规范人工判断。浏览器工具和大规模验证需用户同意。

最后报告实际改动、定向验证、未确认事项与验证边界；如发现规则缺口，只更新主规范对应章节，不新增平行设计文档。
