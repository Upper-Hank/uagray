# 组件演进规则

## 核心目标

Uagray 服务于其他项目。每次扩充都应让项目更容易复用组件，同时保持灰阶、留白、柔和圆角、轻阴影与克制反馈的一致性。组件数量不是完成度指标。

新增外观依据 [P10 有限扩展](design-system.md) 判断必要性、一致性、组合性、可预测性、可用性及维护成本。已撤销的 Outline 候选不作为实施清单；新外观须符合现行边界契约，不重新引用历史提案授权。优先检验现有十条准则，只有明确缺口才修订原则。

## 简洁的边界

- 用少量语义 token 统一颜色、尺寸、圆角与动效；避免为每个组件建立独立风格。
- 保留原生 HTML 属性和语义；只有实际需要才增加 variant、size 或组合层。
- 优先组合现有组件；重复使用需求明确后再提取新抽象。
- 组件层不依赖展示页的数据、hash 路由、文案和业务状态。
- 图标统一来自 Uplus Icon，不维护第二份 SVG。
- 简单交互优先 CSS 和原生元素；复杂浮层如有需求，再评估成熟的无样式交互基础，避免自行堆叠焦点管理代码。
- 样式以 `.ui-` 命名并尽量限定作用域；宿主页面重置、字体资源路径与路由行为必须可独立配置。

## 新组件的完成标准

1. 能解释它在其他项目中的具体用途。
2. 复用已有 token，明确默认、悬浮、按下、焦点、禁用，以及适用的错误状态。
3. 保持键盘操作与原生语义；反馈型组件提供真实操作结果。
4. 提供最小用法、必要属性说明和一个展示示例。
5. 对有状态或复杂交互做定向测试；纯展示变化不机械添加测试。
6. 检查对现有组件、样式作用域和包体的影响。

## 建议扩充顺序

表单、选择、Tabs、反馈、原生 Dialog，以及库构建、类型声明、样式和字体入口已经落地。历史批次见 [需求驱动组件批次](references/history/component-batch.md)。下面只保留仍取决于真实使用的事项。

| 优先级     | 工作                                              | 目的                                                                                     |
| ---------- | ------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 按真实页面 | 动效细化                                          | 按压、进入、退出和幅度仍待具体场景确认，不把现有数值写成全局参数                         |
| 已接入     | Heading、Text、TextList、DescriptionList 文本体例 | 统一标题、正文、有序/无序列表和属性说明；通过公共入口导出，展示配置与压力页复用          |
| 已接入     | ButtonGroup / Pager / ActionRow 外部尺度          | 统一 md 36px / sm 32px 完整外高，按 inset 分配内部尺寸与圆角；组件实现与检查器已同步迁移 |
| 已接入     | Spinner、ToastRegion                              | 等待指示和提示停靠已进入组件库。Button 的 `busy` 表示异步进行中                          |
| 按需       | Menu、Popover、Tooltip                            | 操作菜单、定位浮层、悬停与焦点提示仍待真实页面提出用途后再做                             |

暂不为了覆盖数量建设表格、日期选择器、复杂编辑器、图表等大型模块。

文本体例组件的首个范围是有共同背景与边距的属性说明列表：保留 dl / dt / dd 语义、13px 文本、内容自适应行高、长文本与窄宽排列，并由组件承接一致的分隔归属。正文为 14px。设计规则只维护在 [主规范](design-system.md#正文与文本列表体例)；四类文本组件的名称与 API 已登记在 API 名单，不从这一次压力页的两行文案提取业务属性。

## 气质维护

新组件要融入已有灰阶层级：页面、内容表面、控件外壳、白色选中层。辅助信息降低视觉重量，错误反馈可以使用少量语义色。保持内容密度与间距的一致，不给每个元素添加边框或阴影，也不为了与参考站不同而随意改变已认可的风格。
