## 目标、证据与状态

Uagray 是供其他项目复用的轻量 React 设计系统。可读性与可用性是首要依据：通过少量、明确的组织方式处理复杂信息，让使用者看懂关系、识别操作、理解状态。

参考 anish’s lab 的组织方式和克制反馈，提炼原因，不沿用其品牌、作品、身份或文案。截图保存在 [本地档案](references/anish-lab/README.md)，研究见 [直接核查](reference-inspection.md)与[公开实现核查](reference-implementation.md)。参考站存在不同处理，不能将一个案例的做法推成所有组件的规则。

本文的“已确认”表示用户明确认可；“工作约束”表示本稿提出、需要场景检验的判断方法；“待确认”表示尚无结论，不按通过或违规处理。已有 API 仍按代码运行，[api-contract.md](api-contract.md) 的迁移提案不等于已经发布的接口。

## R1：先说明关系，再增加装饰

**已确认。** 每个可见差异应服务于信息关系、操作范围或状态识别。优先用位置、对齐、间距、文字层级组织信息。

**工作约束。** 新增底色、边缘或阴影前说明它解决的问题。去掉后仍同样清楚的装饰优先省略；去掉后无法识别编辑区、分组或状态的处理应保留。不能以统一为由抹去必要区别。

正例：API 参数名与值在单元内沿同一轴对齐，可编辑值有清楚的输入区域。反例：文字散放在灰面板里，无法分清参数和值，也看不出哪些可以编辑。

## R2：共同底座与内部识别分别判断

**已确认。** 共同底座表达整体关系，内部边界取决于任务。

- ButtonGroup：功能成组不必独立铺底；独立使用时可有共同底座，工具区已经提供边界时可使用 plain。带共同底座的子动作常态融为一体，反馈作用于当前项；plain 组保留子按钮自身表面，不清空主要操作。
- API：属于当前组件的配置任务，在灰展示区内使用白工具栏，与预览共同呈现；字段标明编辑范围，配置不再拥有独立灰块。
- 内容：正文、图片和标题优先依靠排版组织，不按每个 DOM 层级增加卡片。

**工作约束。** 审查完整组合。每层底色都应说明独立用途，不连续套多个几乎相同的容器。

灰色区域可以直接承载文字、图像和元素；内部常态表面按职责选择透明、深一级灰或白色。独立识别不等于一律翻白，按 [表面选择评判顺序](surface-contract.md#表面选择评判顺序) 判断。不能给区域里的每个控件机械套更深灰色。已有共同操作底座时，内部常态融为一体，局部 hover 按已确认策略表达；共同底座和内部操作的关系一起审查。

卡片的灰胶囊是 hover 时出现名称的反馈策略，依附整张卡片，不是独立按钮。参考中常驻白底是可单独点击的外链按钮；出现时机、表面和边界由这两种不同语义决定。

白配置工具栏围合当前组件的参数操作，其内部灰字段表达编辑范围。不可仅因这种层次判定多余；应检查工具栏是否服务当前任务。白取色面板中的灰 HEX 输入、白结果面板中的灰内容区同样有明确内部用途。操作组为每个普通按钮默认添加白底与阴影，会丢失共同底座的作用。

## 环境色模型 · 2026-10-10

**已确认，已推广至全部组件。** 调用者只声明意图，颜色由所在环境决定。完整契约、变量表与角色划分见 [环境色与表面契约](surface-contract.md)，本节只保留摘要。

- 意图：Button `emphasis="strong | default | quiet"`、`tone="neutral | danger"`；Badge / Alert `tone="neutral | success | danger"`。旧 Button `variant` 在 beta 期间映射到新属性，已标记弃用。
- 环境：页面、灰色区域（Surface 默认）、白色层（Surface raised、Dialog、Toast、菜单、ColorPicker）各自重新指定环境契约变量，普通控件填充只比所在背景深一级；区块、独立层与 strong 强调按角色处理。

| 环境             | control | hover   | region  |
| ---------------- | ------- | ------- | ------- |
| 页面 #fbfbfb     | #ececec | #e4e4e4 | #f2f2f2 |
| 灰色区域 #f2f2f2 | #e4e4e4 | #dbdbdb | #ffffff |
| 白色层 #ffffff   | #f2f2f2 | #e8e8e8 | #f2f2f2 |

- 角色：控件读取 control；区块（Disclosure、代码、上传、展示卡、导航卡）读取 region 并成为子项环境；白色只用于独立层；strong 跨环境不变。
- 成组：带底座的组与 SelectionBar soft 为子项把 control 设为透明，悬停叠加 overlay；plain 组按下项使用 `--ui-selected`。
- 核查入口：展示站「规范 → 环境矩阵」，覆盖按钮、字段、选择、状态与区域五个族类。

## R3：限制表面数量，按用途消费颜色

**已确认，由环境色模型实施。** 页面基底上可以直接呈现文字与内容，也可以用灰色区域承载作品、操作和配置。表面数量由环境模型限定：每个环境只提供 control、region 与白色层三种填充，tone 按环境配对；不沿 DOM 嵌套逐层加深灰色，区块不嵌套。

| 角色       | Token        | 当前浅色值                  | 用途                                       |
| ---------- | ------------ | --------------------------- | ------------------------------------------ |
| 页面       | background   | #fbfbfb                     | 正文及无须独立铺底的内容                   |
| 区域       | surface      | #f2f2f2                     | 实践、配置、图像或相关内容的共同承载       |
| 白色层     | raised       | #ffffff                     | 浮层、选中块、键帽、工具条、灰区域中的区块 |
| 控件基础值 | control-on-* | #ececec / #e4e4e4 / #f2f2f2 | 只供环境容器引用，组件读取 `--ui-control`  |

这是 Uagray 当前映射，不是参考站完整规范。组件名称不决定固定底色；环境由容器声明，实现不探测祖先背景。白色层不能据名字推断必须有阴影。

action/on-action、danger-action/on-danger 成对表达强调和危险动作。success/danger 用于真实反馈。颜色内容（取色区域、图片、海报）不受中性 UI 色阶限制，外围控件仍遵守规则。

## R4：边缘与阴影服务分离和识别

**已确认硬性规则。** 常驻对象描边只允许用于白底且具有明确强调或分离职责的对象；白底不自动意味着描边或阴影。灰底、深一级灰与透明对象不得带常驻轮廓，不能用 border-block 或 inset shadow 绕过限制。

先用组织、留白和环境一级差完成识别；白色对象仍需强化强调或分离范围时才增加轻描边。分隔线只表达内部内容结构，不围合控件；焦点与错误提示按实际状态出现，分别遵循状态契约。详见 [描边硬性规则](surface-contract.md#常驻描边硬性规则)。

现有 treatment 接口只描述处理能力，不授权任意 tone 与 defined/physical 组合。灰色 Disclosure 上下边线与选择标记 inset 边缘已移除，环境模型的一级差负责识别。

## R5：临时反馈与持续状态分开

**已确认。** hover、按压是临时动作反馈；选中是持续状态；焦点表示键盘定位；错误表示输入问题。

任何 UI 交互状态均不得改变字重或图标描边。hover、按压、选中、焦点、禁用都保持同一文字与图标重量；文字内容中的强调仅在用户明确允许的场景采用更大字重。

| 情况                   | 约束                                                                   |
| ---------------------- | ---------------------------------------------------------------------- |
| Segmented 常态         | 标签与计数同为浅色                                                     |
| Segmented hover / 选中 | 只有标签变深，两者颜色相同；计数保持浅色，字号字重不变                 |
| Segmented 选中项       | 白色指示块表达当前项；hover、再次点击不增加反应                        |
| Segmented 切换         | 指示块平滑移动并改变宽度，无回弹；标签进入、移出均有颜色过渡           |
| 普通独立按钮           | 图标与文字同色；允许前景、背景共同改变，废止“hover 不改文字色”的旧限制 |
| 普通操作组             | 底座保持，仅当前子按钮显现局部 hover，常态没有独立表面                 |
| disabled               | 不响应动作，并具有可辨认的不可用表现                                   |
| 文字输入焦点           | 仅 Tab 定位显示轻量提示；鼠标点入、正常输入不显示外圈                  |

参考 Share 的 #ececec/#404040 → #e4e4e4/#171717，以及箭头局部黑色 6% overlay，是记录的观察值，支持独立按钮和组内按钮采用不同反馈，不要求所有组件照搬数字。

**待确认：** 其他选择控件是否采用 Segmented 的前景策略；不同按钮的按压范围。箭头无按压、普通按钮有按压的观察不能推导成全部按钮都缩放。

## R6：文字与图标保持轻而可读

**已确认（2026-10-10 修订）。** 两档字重：界面与正文 400（regular），标题 500（medium，包括页面标题、小节标题、对话框标题与状态标题）。按钮、标签、数值、选中目录与辅助信息均为 400。字体保持 IBM Plex Sans / Sans SC，不更换；450 Text 资源暂不消费。代码和参数名可用等宽字体并使用同一常规字重。图标用官方 @uplus-icon/react，默认 weight=1.25、absoluteWeight=true，图标和所属动作文字共享 currentColor。

label、control-value 默认 13px/400；status-title 默认 16px/500。button 与计数消费 400。只有标题角色消费 medium；正文、strong 与状态不自动加重，内容强调需另有明确授权。交互状态不改变字重，Segmented 各状态字重一致。

细边缘 `--ui-border-soft` 为 6% 黑（浅色主题），与参考站的共享表面边缘一致。

同一角色的字号、字重、前景调整应修改 Token 或角色映射，不逐组件打补丁。内容图标允许配置，关闭、展开、增减等结构图标保留操作语义。

## R7：尺寸由组件和宿主共同负责

**工作约束，沿用既有分工。** size 控制几何与排版，不改变颜色。

| 类型                                                   | 默认宽度职责                     |
| ------------------------------------------------------ | -------------------------------- |
| Button、Badge、Switch、操作组                          | 随内容；图标按钮保持明确点击尺寸 |
| Input、NumberInput、Textarea、Select、Slider、Progress | 填充宿主分配的宽度               |
| Disclosure、Alert、EmptyState                          | 填充宿主，不强加业务固定宽度     |
| Surface、Layout                                        | 承接正常布局，宿主决定排列和宽度 |
| ColorPicker、Dialog、Drawer                            | 合理默认尺寸，并适应有限视口     |

间距、圆角、高度消费共享尺度。内外控件高度可以不同，但整体对齐；视觉细线不能导致难以操作的命中区域。精确宽度由宿主决定，不统一增设 width/fullWidth API；需明确 className、style、ref 指向根容器还是实际控件。详情示例宽度不等于组件默认宽度。

### 圆角与组合几何契约

**已确认，2026-10-10 统一修订。** 圆角由对象尺寸与轮廓关系决定，不由组件名、背景色或 DOM 层级决定。基础尺度继续为 0 / 4 / 8 / 12 / 16 / 24px，不新增基础档位。

| 对象                           | 圆角 | 消费方式                                         |
| ------------------------------ | ---- | ------------------------------------------------ |
| 18px 选择标记、24px 键帽       | 4px  | radius-1                                         |
| 32px 小控件、选择轨道内部项    | 8px  | radius-sm                                        |
| 36px / 44px 普通控件、图标动作 | 12px | radius-control；图标按钮必须与同尺寸文字按钮一致 |
| 独立内容卡、反馈块             | 16px | radius-card                                      |
| 大面积承载、Dialog / Drawer    | 24px | radius-surface，不用于单个小动作的外壳           |

**组合先确定实际 inset，再派生外圆角：外圆角 = 内圆角 + 两条对应轮廓之间的留白。** 计算的 inset 包含影响轮廓距离的 padding 与必要边缘，不包含无关的组间 gap。此关系与 [CSS 圆角的内外边缘定义](https://www.w3.org/TR/css-backgrounds-3/#corner-shaping) 一致；这里是项目对独立嵌套对象的组合约束，不是浏览器自动推导子元素圆角。

- 普通动作组保留 36px 子控件，内圆角 12px、inset 4px、外圆角 16px；全部为 small 时保留 32px 子控件，内圆角 8px、inset 4px、外圆角 12px。不得套组后再压成 28px 或用另一档圆角覆盖。混合尺寸采用共同的 12px 内部反馈圆角，保留各自高度。
- plain 组只排列对象，不改写子项的尺寸和圆角。单个外链动作使用一个控件表面，不制造共同底座；多项外链与分页采用动作组契约。
- Segmented / Tabs 选中块与内部反馈为 8px，inset 4px，轨道外圆角 12px。文字标签不再自动成为胶囊。
- Select 菜单内部项为 12px，inset 4px，外圆角 16px。紧凑工具层使用相同关系；宿主增加 inset 时同步派生外圆角。
- 字段面板与 API 工具区内部对象 12px、inset 12px时，外圆角为 24px；inset 16px 时允许派生 28px，不新增基础 Token。ColorPicker 的主要取色区域为 8px、inset 16px，面板为 24px。
- 大面积教学承载不强求与相距较远的组件同心，不为满足公式制造嵌套。层的阴影、描边必须单独满足表面契约，不能用厚白圈补救圆角。

圆形例外仅用于 Radio 标记、滑块、取色定位点；细轨道与滚动条可以用 radius-full 保证端部连续。普通按钮、标签、Badge 和图标动作不因短小而自动使用 full。裁切贴边处可为 0；Drawer 只有面向内容的两角使用 surface 圆角。

CSS 与 Motion 必须读取同一个局部圆角变量。size 决定独立控件的圆角档位，只有具有共同底座的组可统一内部反馈圆角。不得重复声明圆角、写裸 6px / 24px 绕过 Token，或用 !important 掩盖覆盖冲突。几何审查覆盖独立、small、混合尺寸、plain、soft 与浮层组合；浏览器视觉验收须另经用户授权。

工具栏必须同时满足视觉秩序与功能。必要时可以多行，但多行不能补救把字段组件生硬插进工具栏的问题。应先定义操作轴、标签/数值安排、命中范围和子项对齐，再确定布局。SaaS 表格要检查行头与内容、状态、选择框和操作的对齐及可辨认性；灰区域的控件不能直接沿用浅页面上的灰底预设。

同一工具栏沿同一操作轴排列的控件，应对齐外部高度，不能只对齐中心或文字。分段选择器以完整轨道外高参与对齐，不能拿内部选项高度与相邻按钮比较。默认工具栏统一消费 control（36px）；不得将 small（32px）按钮与默认选择器混排，除非已明确独立操作分组与尺寸层级。局部修复优先使用组件现有 size，不写额外高度覆盖 Token。

连续调节控件与对应重置属于同一操作组：标签、轨道、数值和重置沿同一行排列，调节区与重置之间用竖向分隔线区分职责。宿主先分配可伸缩的轨道宽度，不以固定宽度将重置挤到独立一行；确需多行时按完整任务组调整。教学展示区已提供承载基底时，工具组直接放入其中，不重复包裹灰色面板。

滚动条不能改变布局宽度。页面根滚动区与组件内部滚动区使用 `scrollbar-gutter: stable`，在占位式滚动条出现前预留空间；内部滚动区使用统一的 `.ui-scroll-area` 契约。工作台由目录和内容区承担滚动，隐藏滚动条的规则仅作用于工作台，不通过全局禁用滚动或裁切内容规避宽度变化。覆盖式滚动条沿用系统行为，不另加手工补偿宽度。

## R8：过渡表达变化，状态及时响应

**已确认。** 颜色进入、移出均有短暂过渡；宽度与指示块平滑移动，不回弹、不闪烁。快速操作能够中断当前过渡，不留下旧状态。

## 组合职责与规范阅读 · 0.5

基础组件固定功能、可访问语义和操作能力；组合组件负责共同边界、子项安排、尺寸协调、对齐与选择表达；页面负责任务、阅读顺序、主次、宽度和出现时机。颜色上下文不能代替这三个层面的判断。

ButtonGroup 新增 tone="plain"：保留功能组，不重复铺底；plain 组中 aria-pressed 选择使用局部灰底，重量保持固定。独立操作组仍默认 soft。SelectionBar 默认 plain、按内容宽度排列；数量摘要通过 summary 显式提供，与动作使用同一控制轴，不再自动生成“已选几项”。显式 tone="soft" 才增加共同底座。宿主按任务分配位置，而不是默认铺满页面。

工作台版式操作在白工具区中使用 plain 组，避免额外灰底与白色选中块。SaaS 批量栏不再铺满宽度居中；表格普通状态直接呈现文字，状态/选择/操作列沿共同列轴排列。Badge 仍用于实际需要独立标签识别的场景，不是所有状态的默认外壳。

规范页为阅读文档，每条规则配常驻说明和对应可操作演示，宽空间并列、800px 以下顺序堆叠；不使用组件详情的实践画布、API、代码折叠模板。文字负责解释目的、边界及反例，演示只验证该条关系。修改规则时同步文本、组件组合与案例，不能只改 Token 或单件演示。

### 规范阅读页的说明与演示空间

说明正文只在规则阅读区呈现，不为每个演示默认增加重复图注。图注适用于实际内容名称或理解图像所必需的信息；组件内部保留实际数值、状态和必要操作名称，不添加解释布局的文案。

规范页灰演示区使用专用 240px 最低高度，保留对象周围的观察空间，内容增长时自然增高。这是演示宿主的布局约束，不是所有 Surface 或灰底组件的尺寸规则。详情正文使用受限阅读宽度，区块之间留出清晰间隔；图解空间由内容与任务决定，不仅由子组件的高度撑开。

### 组件详情的 API 工具栏

配置和预览共同属于一个任务。API 不再是独立折叠块，而是灰展示区内的白配置工具栏；参数名与控件组成统一的浅灰横向参数单元，名称在左、值在右；长文本通过参数按钮按需展开到工具条下方。字段数量不同可形成多行，不隐藏必要参数，也不靠固定定位覆盖预览。重置与配置共处，生成用法保持独立。

该工具栏包含原生字段与自然 Tab 顺序，使用命名 group 语义；不套用需要方向键导航的 ARIA toolbar 行为。此次是完整迁移，后续可继续依据参数数量优化组织。

### 控件文本选择

按钮、选择项、字段标签、快捷键及导航控件等用于操作的文案默认不可选中，避免点击或拖动产生无意义的文本选择。该规则不改变点击、键盘焦点或可访问名称。

输入框、文本域、正文、代码、可复制结果及有实际阅读/复制用途的内容保留文本选择；不在 Surface、Layout、Dialog、Disclosure 或页面根部全局禁用选择。特殊场景可使用库的 ui-selectable 类明确恢复文本选择，避免通过取消指针事件处理。

### 组合留白契约：从边界到可见内容核查

组件内部的留白正确，不代表组合后的留白正确。组合必须同时规划外缘留白、单元之间的间距、单元内部间距与命中范围；不能只给容器同一个 padding，再假定两侧自然平衡。

- **外缘留白：**比较容器内缘到首尾可见内容的距离，包括容器 padding、子单元 padding 和图标自身的绘制内距。首尾子项类型不同，实际距离仍应有一致、可解释的视觉关系；不要求不同内容机械使用相同 CSS 数字。
- **单元间距：**比较相邻可见内容的距离，而不只比较 gap。可见间距包含前一单元尾部留白、容器 gap、后一单元起始留白。组内关联和组间分离应有明确区别，不能因混入 Button 而偶然增大。
- **组合单元：**图标与其说明构成一个信息单元，按钮构成动作单元，标签/输入/数值构成字段单元。信息单元不能依赖相邻按钮的内部 padding 来获得自己的外缘留白；也不能为补留白把普通说明伪装成按钮。
- **留白职责：**容器负责共同外缘，子单元负责自身内容与命中区域。使用小 inset 操作底座的前提是子项已经具有协调的内容留白；裸图标、文字、按钮混排时必须重新核查这一前提。plain 只说明没有独立底色，不意味着按钮取消尺寸或内部 padding。
- **尺寸变化：**首项、末项、纯图标、纯文字、图标加文字、长标签、不同 size 以及换行后的行首/行尾都应重新成立。调整基于单元契约，不添加针对某个图标或某一张截图的 first-child margin 补丁，不修改上游 SVG。

核查顺序为任务单元 → 单元内容/命中范围 → 共同外缘与组内/组间距离 → 主轴和基线 → 宽度变化。评审必须查看实际组合的可见内容包络；共享 Space Token 或 align-items:center 本身不构成通过证据。精确数值由尺寸角色和组合用途确定，不能把一个工具栏的值推广到所有灰底或白底容器。

### 组合留白的实现约定

共同工具底座可使用 4px 容器 inset，但内部必须是完整单元。ui-toolbar-row 中，普通按钮、无底座选择组中的按钮、ui-toolbar-info 信息单元与 ui-toolbar-field 字段单元使用 padding-control（12px）横向内容留白，单元之间使用 gap-control（8px）。图标与名称在信息单元内部用 gap-control 连接；不把普通文字变成可点击按钮。首尾可见内容由容器 inset 和单元留白共同确定，图标上游绘制内距保持不变。

有自己底座的选择组保留其内部 inset；它是一个独立组合，不能为了抹平层级而重复增加按钮留白。无底座批量栏以页面内容轴对齐；带底座批量栏的计数使用与动作协调的内容留白。上述契约仅适用于共同工具组合，不能覆盖所有 Button、Field 或阅读区域。

组件详情的画布背景与组件 API 分开管理，但实例与配置工具行共用一个 preview 区块。背景选择与组件名称同行，浅色/灰色/白色选项使用带统一描边的圆角颜色样本；该描边服务颜色辨识，不扩展灰底组件的常驻描边规则。背景选择不改变组件参数、生成代码或 API 重置范围。

API 按功能 part 组成紧凑工具条，不显示维度标题；同类参数并排，以内部竖线划分，不以整张配置卡或独立参数底色包裹。灰画布采用白工具行，白画布采用灰工具行；内部单元消费所在环境的 element 资源，编辑控件透明，不再叠加字段背景。单元保持 44px 最小高度、12px 横向留白，工具行 inset 与单元间距均为 8px，外圆角按 12px + 8px = 20px 计算。按容器宽度自动形成等宽列，240px 为列宽基准；空间不足时整项换行，名称和控件不拆散。

长文本在所属维度行内展开，收起保留值，重置关闭编辑区。工具行采用 tonal 表面，不自动获得描边或阴影。重置是尾部动作，不伪装为参数或增加解释文本。配置保留自然 Tab 顺序，不修改可复用 Field 的默认布局。

### 解释性文案的准入规则

不自动生成“实践”等区块提示、演示题注、图注、说明性尾句或重复旁注；组件默认不携带解释自己样式、布局或设计意图的文案。规范页通过正文陈述规则，演示负责呈现规则，不再附加一套重复说明。案例页表达实际内容与操作，不讲解自身用了什么底色或工具栏。

新增解释性文本须同时满足：有明确读者任务；现有名称、正文或交互不能表达该信息；删除后会损失必要理解。按用途安排到正文、字段帮助/错误、操作指导或状态反馈，明确它解释的对象与显示时机，避免同一信息多处重复。题注/图注只用于识别或区分实际图像内容、提供必要来源或解释不可直接辨认的信息，不作为演示模板的默认结构。

参数名、组件名称、实际内容标题、必要状态反馈及可访问名称不属于冗余注释。保留它们；不能以清理解释文案为由损害可读性和可用性。

### 同类选择器共享视觉与动效

采用胶囊选择条外观的 Tabs 与 Segmented 共用选择底座、单元尺寸、文字反馈与滑块几何。底座使用 control，选中滑块使用 raised 与统一浅边缘/轻阴影；父级灰区域不得自动把这组关系翻转。选择器放在灰区域时可由白色工具层提供必要分离，不用加深一层灰补救。

hover 只让未选项文字变深，与选中文字一致；移出渐变恢复。选中项 hover 与重复点击不产生新的响应。选择通过同一滑块移动并改变宽度，使用统一无回弹过渡，换行时同步位置与高度；不改变字体重量或图标描边。Tabs 保持 tablist/tab/tabpanel 与内容切换语义，Segmented 保持 radiogroup/radio 值选择语义，不为共享外观互换语义。

### 独立工具层的分离契约

配置工具、悬浮工具和视图工具共用 ui-tool-surface 的几何。配置显式使用 Surface treatment="defined"；悬浮和视图工具使用 physical。shadow 为 edge 与 elevation 的组合，Physical 不重复叠加 border；Tonal 没有额外边界。

普通内容 Surface 和 Soft 动作不因灰环境获得阴影；action-shadow 自动映射已经取消。共同组边界交由组合承担。按 P04/P05/P07 使用有限的 Tonal、Defined、Physical 处理，不新增自由拼接 fill/border/shadow 的组件 API。

### 案例页以阅读单元组织内容

灰底必须说明一个共同承载范围：工作台、图像/交互展示或相关内容的完整组合。不能按每个指标、每段说明、每个表格、每个设置区自动生成一张灰卡。先以标题、留白、列轴、行距及必要分隔组织阅读，再判断是否确有背景需要。

SaaS 概览指标直接沿阅读轴排列；搜索、筛选和创建构成操作行；项目表格使用页面背景、固定列关系和行分隔，不再套灰容器。状态直接阅读，编辑/选择保持控件识别；设置作为正文中的字段区域。海报正文不再复用灰色 Disclosure，实际工作台与图像展示保留灰承载。详情的相关元数据可共用一块灰区，不因本次清理机械删除所有灰色。

### 详情页阅读字号

以 action-camera 参考页的实际 CSS 测量为依据，区分主标题 22px / 1.25、简介 15px / 1.625、正文 14px / 1.625、小节标题 15px / 1.5、信息列表名称 13px / 1.5、信息列表内容 13px / 1.625、图注 12px / 1.5。简介与正文保留 65ch 最大阅读宽度，标题后的简介间隔 12px，小节标题后的正文间隔 8px。应用于案例阅读角色，不修改全局控件尺寸或将全部文字统一放大；标题使用 500，正文、简介、信息列表与图注使用 400。

### 折叠阅读区与内部动作

折叠标题是共同容器的一部分，使用透明动作，不额外增加阴影。标题和辅助操作可共用一行，但辅助操作须为同级元素，不嵌入折叠按钮。阅读区只保留一套必要的展开机制：组件用法由 Disclosure 整块收起，内部直接呈现完整代码，长内容在代码区内滚动，不再套渐隐与“展开完整示例”。撤销单一白色阅读边界：文本体例读取环境 region，标题、复制和正文共同组织。有 head/content 分隔线时 Copy 必须透明；无分隔线时可透明或采用深一级灰，按操作识别需要判断。

独立 ExpandableCode 保留展开功能，表面与附属操作按 [文本体例契约](surface-contract.md#文本体例) 判断；不再强制白色内容表面与灰色复制/展开按钮。代码、完整结果等自有表面的组合必须明确局部消费契约；不能给普通按钮统一加阴影作为分离修复。

## v0.1 本轮实施决策 · 2026-10-10
