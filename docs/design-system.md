## 阅读与使用

- 设计单件：阅读设计原则、环境与表面、边界、几何、文字、交互及对应组件契约。
- 设计组合与页面：先确定任务与关系，再阅读组合留白、宽度职责和展示实践；不能只看单件截图。
- 实现与检查：使用本文的开发流程，按需查 [Token 工程映射](tokens.md)、[API 名单](api-contract.md)与[调试工具契约](playground.md)。

本文未标注为待讨论的条款是当前执行基线；既有规则中的工作约束是工程判断依据，不能冒充已完成的视觉实验。待讨论项集中在文末，不混入执行规则。源码记录当前能力，本文定义目标；发现偏差时明确记录，不以现有实现自动改写规范。API 的发布状态与兼容要求以 API 文档、类型声明和 CHANGELOG 为准。

## 设计目标与原则

Uagray 是供其他 React 项目复用的轻量灰阶设计系统。优先可读性、可用性、视觉一致与实际复用价值。通过位置、对齐、留白、上下文色差与克制反馈组织信息，不以组件数量或装饰数量衡量完成度。

保留 P01–P10 编号，方便展示站与既有讨论定位；不再并列维护另一套 R1–R10 原则。

| 编号 | 原则           | 执行判断                                                               |
| ---- | -------------- | ---------------------------------------------------------------------- |
| P01  | 独立层级       | 分别判断信息重要性、对象归属与空间覆盖，不用一条色阶表达全部关系。     |
| P02  | 连续基础环境   | 页面是连续环境，不为每个结构分区自动铺底。                             |
| P03  | 上下文表面     | 组件声明职责和意图，环境提供颜色；组件名与 DOM 深度不决定底色。        |
| P04  | 表面与边缘独立 | 填充、描边与阴影各有职责，白色不自动表示浮起。                         |
| P05  | 最小充分对比   | 使用足以识别对象、状态和操作的最少视觉属性；柔和不能牺牲可用性。       |
| P06  | 有意义的容纳   | 连续阅读共享表面，离散对象按实际识别需求建立范围。                     |
| P07  | 边界归属       | 由承担共同关系的对象建立边界，不让父子重复表达同一范围。               |
| P08  | 语义交互       | 反馈服从组件交互模型，hover、选中、焦点和错误分别设计。                |
| P09  | 受控强调       | 将高对比资源分配给有明确优先级或状态识别需求的对象。                   |
| P10  | 有限扩展       | 新外观须有真实需求，能与现有系统组合并具有可预测行为；先检验既有规则。 |

新增视觉处理前，说明对象、任务、要辨认的关系以及现有表达为何不足。不要把参考作品中的一个案例推广成所有组件的规则，也不要为了“统一”抹去必要差异。

## 环境与表面

### 环境色契约

**调用方只声明意图，颜色由所处环境决定。** 环境容器显式建立上下文，不探测祖先实际背景，也不按 DOM 深度逐层加深灰色。

| 环境     | 建立方式                                      | 控件填充                | 内容区块  |
| -------- | --------------------------------------------- | ----------------------- | --------- |
| 页面     | 根环境 `background`                           | `control-on-background` | `surface` |
| 灰色区域 | Surface 默认环境                              | `control-on-surface`    | `raised`  |
| 白色层   | Surface raised、Dialog、Toast、菜单与取色面板 | `control-on-raised`     | `surface` |

浅色、深色使用相同职责结构；深色不机械反转基础灰阶。实际色值唯一维护在 `src/ui/tokens.css`，工程变量对照见 [Token 文档](tokens.md#环境变量映射)。`raised` 是兼容变量名，不自动表示空间抬升。

### 对象角色

| 角色   | 消费与职责                                                   | 约束                                                                                     |
| ------ | ------------------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| 控件   | 读取 `control`，例如按钮、字段、选择轨道与中性标签           | 普通常态与背景保持环境规定的一级差，不用描边补救灰上灰。                                 |
| 区块   | 读取 `region`，例如 Disclosure、代码、上传区、展示卡与导航卡 | 与环境交替，并用 `region-*` 建立子项环境；区块不嵌套，需要内部组织时采用控件或透明布局。 |
| 独立层 | 使用 raised，例如菜单、弹窗、选中块、键帽与滑块              | 根据覆盖、分离或实体职责决定边缘，不自动同时添加描边和阴影。                             |
| 强调   | strong 使用 action 或 danger-action                          | 跨环境保持强调意图；禁用后退回控件填充与禁用前景。                                       |

图像、海报、取色渐变等真实内容允许彩色，外围 UI 仍遵守环境契约。状态 tone 的前景与底色成对适配环境，不能只替换其中一个。

### 操作与共同底座

Button 用 `emphasis="strong | default | quiet"` 表达强调，用支持的 `tone` 表达语义，不把白色、灰色或阴影变成调用方的颜色选项。主要提交与危险确认按任务使用 strong；次要操作使用 default；附属操作通常使用 quiet。API 配置的“重置示例”已明确采用 default 灰底，是该工具中的已确认选择，不推广成所有重置按钮的默认规则。 danger + default 使用当前环境的 danger-fill 与 danger-on-fill 前景，悬停在同一语义底色上轻量加深；danger + quiet 常态保持透明并使用 danger 前景；danger + strong 使用 danger-action / on-danger。disabled 使用中性底色与禁用前景，quiet 继续透明；busy 保留当前强调与语义配色，禁止悬停和按压反馈。

带共同底座的动作组读取 control，普通子动作常态透明，只在当前项出现局部反馈；strong 保留识别。plain 组仅排列与表达归属，不清空子按钮表面。一个动作不套无用途底座。现行属性名及旧名称兼容映射见 [API 名单](api-contract.md)。

Tabs / Segmented 的轨道读取 control，选中块为 raised 独立层，不自动再套一层工具外壳。白色工具层建立自身子项环境，不在内部另写固定灰值。

## 边界语言

### 表面、描边、分隔与阴影

| 处理       | 用途                             | 使用边界                                                |
| ---------- | -------------------------------- | ------------------------------------------------------- |
| 留白与对齐 | 表达归属、阅读轴、组内与组间关系 | 优先建立；不能靠容器铺底掩盖排列问题。                  |
| Tonal      | 通过表面色差识别范围             | 不附加常驻对象轮廓。                                    |
| Defined    | 明确对象轮廓                     | 只用于白色层且有明确强调或分离职责。                    |
| Physical   | 表达覆盖、浮动或实体关系         | 只用于合法独立层；边缘与投影分别判断，避免重复 border。 |
| 内容分隔线 | 区分阅读单元或内部结构           | 不围合控件，不借上下线模拟被禁止的对象轮廓。            |

**常驻对象描边只允许用于白色层且具有明确强调或分离职责的对象。白底是必要条件，不是自动加描边的理由。** 灰底、透明控件及区块不得用 border、inset shadow 或伪元素绕过限制。焦点、错误等真实状态提示不属于常态装饰描边。

Surface 的 tone 与 treatment 分别描述表面和边缘处理能力；接口存在不等于任意组合都被授权。普通按钮、灰区域与内容块不因承载颜色而自动获得阴影。

先判断关系与表面色差是否足够，再判断轮廓或空间分离是否必要；这不是每个组件都必须经历的升级阶梯。独立层可有合理实体处理，正文无需为了“完整”补背景与外框。

独立层需要细边缘时，将半透明边缘绘制在自身表面内侧，使其叠加底色稳定，避免外侧边缘随宿主背景变化而消失或被裁切。投影仍绘制在外侧；不重复叠加 border 与边缘 shadow。此规则同样适用于深色主题对应的 raised 层，不因其实际色值为灰色而取消必要的分离边缘。

### 软边界与渐隐边界

**已确认方向。** 以现有 Expandable text（`ExpandableCode`）为参考，软边界首先依靠表面色差、圆角、留白与对齐建立清楚的范围，不默认叠加常驻描边或阴影。柔和不等于模糊：内容归属、操作范围与可编辑对象仍须能够识别。焦点、错误与独立层的分离继续遵守各自契约，不因软边界而削弱。

区分两种职责：外部的表面边界表达对象范围；内容末端的渐隐边界表达“内容仍在延续，当前未完整展示”。渐隐不是阴影，也不是容器轮廓，不改变环境色模型或表面层级。

渐隐边界遵循以下约束：

- 只用于实际存在隐藏内容的折叠长文或溢出内容。完整内容、普通卡片和常规控件不默认渐隐；内容已全部可见时移除渐隐。
- 沿内容被截断的方向逐渐融入承载表面。渐隐终点与实际承载表面同色，使用该环境的语义变量，亮暗主题均不能硬编码白色或黑色。
- 范围根据文字行高、可见区域与实际遮挡量确定，保留足够的完整可读内容，不遮住标题、必要操作或状态。实现根据本组件文字行高派生渐隐范围，并受可见区域比例约束，不沿用固定 96px，也不把该组件参数提升为全局 Token。
- 展开、加载更多等必要操作保持清楚可见，不随正文渐隐。渐隐只是内容延续的线索，不能替代操作名称与展开状态语义。
- 装饰渐隐不拦截指针或获得焦点，不作为独立内容交给辅助技术。若截断内容中包含交互元素，须另外管理其可见性与可操作性，不能仅用渐隐遮住仍能聚焦的操作。
- 不默认沿容器四周加柔化、模糊或羽化；不把所有滚动区域改成渐隐边缘。使用前先说明被隐藏的内容与用户如何继续阅读。

本条确认设计方向与使用契约，不表示现有组件已完成全部场景验收。后续实现按真实溢出、短内容、展开状态及亮暗环境进行必要的定向核查；浏览器验收仍需用户授权。

## 几何与排布

### 尺寸与宽度职责

size 声明完整控件的外部尺度与配套排版，不声明内部每一层的高度，也不改变颜色或宿主分配的宽度。支持公共 size 的控件以 `md | sm` 对应 36px / 32px；同尺度的独立按钮、字段外壳、选择轨道和动作组底座使用相同最终外高。组合不因多一层 DOM、padding 或底座而升高。44px 是已有尺寸资源，仅在真实任务明确需要时使用，不因组合自动采用，也不因此新增公共 lg 变体。

**统一高度的思想是先定外部尺度，再分配内部空间。** 独立控件与组内项是不同几何角色：独立控件拥有完整外壳；组内项在共同外壳内组织内容、反馈与操作，不能把独立控件的完整高度再叠加到组底座。此原则同样适用于选择轨道、搜索框与嵌入键帽，不要求每个内部对象都长成完整控件。

| 类型                                                   | 宽度职责                           |
| ------------------------------------------------------ | ---------------------------------- |
| Button、Badge、Switch、动作组                          | 随内容；图标按钮保留明确点击尺寸。 |
| Input、NumberInput、Textarea、Select、Slider、Progress | 填充宿主分配的宽度。               |
| Disclosure、Alert、EmptyState、Surface、Layout         | 承接宿主布局，不强加业务固定宽度。 |
| ColorPicker、Dialog、Drawer                            | 提供合理默认范围，并适应有限视口。 |

同一工具栏沿同一操作轴排列的操作单元对齐最终外高，不能只对齐文字、中心或内部按钮。最终外高按 border-box 计算，包含上下 padding、border 和共同底座；margin 与阴影不计入外高，但可见间距须另行核对。选择器以完整轨道、动作组以完整底座参与比较；同一 size 的完整操作单元必须等高，组内反馈块不参与这项比较。

- 普通操作行的完整外高为 md 36px / sm 32px，不随意混排；独立动作与带底座组共同遵守。完整外高固定后，组内可用高度 = 外高 − 上侧实际 inset − 下侧实际 inset；实际 inset 包含 padding 与必要 border，不能重复计算。
- 标准无描边底座上下各 4px inset 时，md 组内反馈/操作项高 28px，sm 高 24px。这是内部几何，不新增独立按钮 size。若额外边缘占据空间，须共同调整 inset 分配并核对命中与内容，不能让组自动变成 44px / 40px。
- 同一行混用带底座动作组与独立动作时，先确认任务关系与表面归属，再协调尺寸。只有本来无需共同表面的动作组才采用 plain；已经明确需要共同底座的组不得为等高改成 plain。相关动作只有确实属于同一任务组时才合并底座，不能为凑高度把独立任务合并。确需独立表面与带底座组并排时，组件组合层须使完整外壳共同遵守所选尺度，并向组内项分配空间。能力缺失属于组件待补项，不能让宿主随意写高度或增加无用途底座。
- 组内项按内部几何重新分配垂直留白，保留所选尺度的字号、图标及必要命中范围；不能把独立控件任意 scale、缩小字号或裁切内容来凑齐。不同外高仅在任务或层级明确分离时使用，不能以 DOM 嵌套为理由。
- 宽度先分配给完整单元：短动作随内容，搜索等字段承接可伸缩空间，成组动作保留完整范围。宿主使用 min-width、换行和布局约束处理空间不足，不让字段固定宽度挤压其他操作；默认宽度也不应成为字段无法伸缩的下限。
- 内容块与文本列表随内容增长；固定高度、比例或内部滚动必须对应真实任务。窄宽时按完整任务单元换行，不拆散图标与名称、字段与附属标记、动作组内部项。

精确宽度、主轴、基线、换行与滚动由宿主负责。图标绘制区域与命中范围分别处理；不能通过缩小字号或压缩点击范围修补组合问题。

ButtonGroup 的运行时尺寸接入：从实际外高扣除上下 padding 与 border，将可用高度写入共享组内高度变量；继承 Icon 的上限为该高度的一半，并同时受 Button 的配套图标尺度限制。上限不是新的固定档位，显式 Icon.size 不能突破；传给 uplus 的数值与 SVG 实际绘制尺寸一致。默认 md/sm 外高不改变，极小的宿主约束不能据此宣称满足命中条件。ResizeObserver 的结果属于运行时尺寸证据，静态声明检查不模拟 DOM 测量。

### 组合外高的决策与状态契约

**决策顺序固定为：任务与分组 → 完整单元的外部尺度 → 表面归属与真实 inset → 内部空间、圆角与命中分配 → 对齐、间距与换行。** 后一步不得破坏前一步的决定。等高只是组合验收条件之一，不能替代分组、语义与命中检查。

1. 列出同一操作轴上的完整单元及其最终外高。比较实际参与布局的可见控件外壳；不把整块 Field 的标签、提示或错误文字当作输入框外高，也不把滑轨绘制高度当作 Slider 的操作范围。
2. 为同一操作轴选择共同外部尺度，md 为 36px、sm 为 32px。不能采用“先取组合后的最大高度，再把其余控件拉高”的补偿方式；增加底座不能改变尺度。若内容确实无法容纳，先核查所选体例与任务分组，必要时将内容改为独立自适应任务块，而非无限抬高工具行。
3. 由库组件统一承接独立外壳与组内项两种几何角色：组内项高度由共同外高与 inset 计算，字号和图标保持既定尺度，垂直留白由可用空间分配。共享外高、inset、内外圆角变量，不在页面分别覆盖 height、padding 或圆角。图标按钮的可见反馈区域与实际点击区域分别核对，不用空 wrapper、透明边框或额外底座制造等高假象。
4. 组内点击区域可以与反馈块相同，也可以在本组内扩大，但不得侵入相邻项、制造重叠或把底座空白误变为某个动作。每个独立可操作区域满足既定最小命中条件；sm 内部 24px 不是允许继续缩小的起点。可用行高、文字行高与图标必须共同容纳，不通过隐藏溢出宣称通过。没有相应组件能力时登记缺口并补齐，不能去掉必要底座或改变任务关系。
5. 同一操作行中，同级表面上下边缘对齐；文字与图标在各自控件内部对齐。不默认对整排内容使用 stretch；需要适配的是控件外壳，不能把文字、标记或无表面状态拉成同样高度。

| 场景                              | 对齐对象                      | 必须保持的关系                                                             |
| --------------------------------- | ----------------------------- | -------------------------------------------------------------------------- |
| 文字按钮与图标按钮                | 最终控件外壳                  | 同 size 等高，图标绘制区域不代替点击区域                                   |
| 独立动作与带底座组                | 独立外壳与整组外壳            | 保留组底座；先统一外高，再按 inset 分配组内尺寸                            |
| Input / Select / Search 与动作    | 输入或 trigger 外壳与动作外壳 | 字段名称、提示、错误在操作轴外组织，不通过增加 margin 抬高按钮             |
| 选择轨道与动作                    | 完整轨道与动作外壳            | 轨道内的选中块不参与外高比较，保留内部 inset                               |
| Slider / Switch / Checkbox 与动作 | 操作范围及内容轴              | 不放大滑轨、开关标记或勾选标记以填满行高；说明、标记与动作保持可辨认的轴线 |
| Badge / 正文与动作                | 文本或标记的内容轴            | 非操作信息不强制等高，不为对齐补成按钮或增加空表面                         |
| 多行字段或长文本与动作            | 完整任务块与独立操作轴        | 内容自然增长；动作按任务明确顶对齐或单独成行，不继承不必要的 stretch       |

状态变化不得意外切换几何契约：

- hover、focus-visible、disabled、checked、selected 不改变基础外高、圆角、padding 或字重。焦点使用 outline 等不参与布局的反馈；状态描边预留空间，不能在出现时扩大 border-box。
- busy、图标替换、计数和文案变化保留控件尺度；需要的宽度随内容变化，相关位置变化按已有动效规则承接。等待图标不能改变行高，隐藏或显示辅助内容不能泄漏为组 padding 变化。
- 同一组的可用与不可用项使用相同外壳尺寸、内部圆角和对齐方式，即使可用项为 a、不可用项为 button。显式方向子项缺少翻页目标时保留不可用位置，不让组变宽高或改变操作位置；调用方删除整个方向子项则不自动补回。
- 主题与表面环境只改变资源映射，不改变尺寸和分组。窄宽换行后保留每个单元的尺寸、底座与内部关系；行首行尾不通过特殊 margin 补齐。
- 普通工具行的长动作标签默认保持单行，空间不足时按完整单元换行；不能让某一个按钮自行成为两行且仍宣称同排等高。真实需要多行的动作须单独明确内容自适应体例。

### 组合的执行核对

每个新增或修改的组合须记录：任务单元、共同外部尺度、需要的底座、各单元最终外高、由 inset 派生的内部尺寸、内外圆角、反馈区域与点击区域、同级间距、宽度分配和换行单位。核算完整外高 = 上侧 inset + 内部高度 + 下侧 inset，不能只登记子控件高度。核对默认、禁用/不可用、busy、长文案及窄宽状态；不适用的状态说明原因，不机械给所有组件增加状态。

可静态计算的外高、inset、圆角与间距关系登记到源码检查器；涉及语义分组及状态分支的实现核查不能被数值检查替代。脚本通过只能证明已登记声明，没有登记或无法计算的组合明确标为未覆盖，不能据此声称不会出现意外。实际布局与光学对齐继续遵守浏览器验收的授权边界。

分享与左右翻页的已确认场景：分享保持独立动作，左右翻页保留共同底座；md 的两者完整外高均为 36px，翻页内部项按 4px inset 分配为 28px。plain 不作为该场景的替代方案。

ActionRow 的职责是排列完整任务单元并协调共同尺度，不能因为存在 contained 组就将独立动作升为 44px / 40px；它不增加表面、改变分组，也不替任意 wrapper 兜底透传尺寸。组内几何由 ButtonGroup / Pager 承接，行层与组层不得各自再叠加一次高度。混合 size 不因代码支持而成为默认允许的组合。

ButtonGroup / Pager 已按统一外部尺度实现，ActionRow 仅排列单元、不再抬高独立动作；源码检查器登记完整外高、内部高度与 inset、内外圆角及组内图标尺寸。检查通过仍不替代实际布局与命中的视觉验收。

### 圆角与组合几何契约

圆角由对象尺寸与轮廓关系决定，不由组件名、背景色或 DOM 层级决定。基础尺度继续为 0 / 4 / 8 / 12 / 16 / 24px，不新增基础档位。

| 对象                           | 圆角 | 消费方式                                         |
| ------------------------------ | ---- | ------------------------------------------------ |
| 18px 选择标记、独立 24px 键帽  | 4px  | radius-1；嵌入键帽另按对应轮廓关系计算           |
| 32px 独立小控件外壳            | 8px  | radius-sm                                        |
| 36px / 44px 普通控件、图标动作 | 12px | radius-control；图标按钮必须与同尺寸文字按钮一致 |
| 独立内容卡、反馈块             | 16px | radius-card                                      |
| 大面积承载、Dialog / Drawer    | 24px | radius-surface，不用于单个小动作的外壳           |

**组合先确定实际 inset，再派生外圆角：外圆角 = 内圆角 + 两条对应轮廓之间的留白。** 计算的 inset 包含影响轮廓距离的 padding 与必要边缘，不包含无关的组间 gap。此关系与 [CSS 圆角的内外边缘定义](https://www.w3.org/TR/css-backgrounds-3/#corner-shaping) 一致；这里是项目对独立嵌套对象的组合约束，不是浏览器自动推导子元素圆角。

固定尺度的操作控件按外壳反推：先选外高与外圆角，再以实际 inset 计算内部高度及内圆角；上述圆角等式用于核对，不能成为把外壳不断加大的理由。内容自适应的菜单、面板与阅读区域仍按其任务和内容分配空间，不把工具行的 36px / 32px 套到整块内容。圆角关系与高度关系分别计算，不能把圆角数值当作高度或命中尺寸。

- 普通动作组从外部尺度反推内部轮廓：md 外高 36px、外圆角 12px、inset 4px，内部项高 28px、圆角 8px；sm 外高 32px、外圆角 8px、inset 4px，内部项高 24px、圆角 4px。CSS 与 Motion 读取同一派生变量，不沿用独立按钮的圆角再叠加 inset。不同 inset 须重新核算，不能只改高度或只换圆角。
- 反馈块尺寸不直接规定图标绘制尺寸或点击范围。独立图标按钮保留对应外部尺度的方形外壳；组内图标项按内部高度组织视觉区域，命中按组内操作区域契约核对。禁用项与可用项采用相同几何，链接与按钮不因标签种类不同而出现差异。
- plain 组只排列对象，不改写子项的尺寸和圆角。单个外链动作使用一个控件表面，不制造共同底座；多项外链与分页采用动作组契约。
- Segmented / Tabs 的 md 轨道遵守 36px 完整外高：内部反馈高 28px、圆角 8px，inset 4px，轨道外圆角 12px。若组件提供 sm 尺度，则完整外高 32px、内部反馈高 24px、圆角 4px、外圆角 8px；此关系不新增其尚未支持的公共 size。文字标签不再自动成为胶囊。
- 搜索框中的键帽等贴近外框的有表面对象，按嵌入关系设计，不机械沿用独立对象圆角。先确定外框尺寸与圆角、子对象尺寸及各侧实际 inset，再计算对应圆角。左右与上下 inset 应共同设计；不相等时不能只取一侧套同心公式并宣称整体同心，应调整布局，或明确它是独立内嵌标记、按自身几何处理。
- 对应轮廓有一致 inset 时，可由外圆角反推内圆角。例如 36px 搜索框、24px 键帽形成 6px 上下 inset；若键帽靠近的一侧也为 6px，外圆角为 12px，则嵌入圆角为 6px。该值由局部关系派生，不新增基础 Token，也不推广为独立键帽圆角。CSS 与 Motion 共用该局部变量。
- Select 菜单内部项为 12px，inset 4px，外圆角 16px。紧凑工具层使用相同关系；宿主增加 inset 时同步派生外圆角。
- 字段面板与 API 工具区内部对象 12px、inset 12px时，外圆角为 24px；inset 16px 时允许派生 28px，不新增基础 Token。ColorPicker 的主要取色区域为 8px，padding 16px 与描边 1px 共同构成 17px inset，外圆角派生为 25px；这是关系计算，不新增基础档位。
- 大面积教学承载不强求与相距较远的组件同心，不为满足公式制造嵌套。层的阴影、描边必须单独满足表面契约，不能用厚白圈补救圆角。

圆形例外仅用于 Radio 标记、滑块、取色定位点；细轨道与滚动条可以用 radius-full 保证端部连续。普通按钮、标签、Badge 和图标动作不因短小而自动使用 full。裁切贴边处可为 0；Drawer 只有面向内容的两角使用 surface 圆角。

CSS 与 Motion 必须读取同一个局部圆角变量。size 决定独立控件的圆角档位，只有具有共同底座的组可统一内部反馈圆角；贴近外框的嵌入对象按上述局部轮廓关系派生。不得重复声明圆角、写裸 6px / 24px 绕过 Token，或用 !important 掩盖覆盖冲突。几何审查覆盖独立、sm、混合尺寸、无底座与带底座的组及浮层组合；浏览器视觉验收须另经用户授权。

### 组合留白契约

先确定任务单元，再分配单元内容与命中范围、共同外缘、组内与组间距离，最后检查主轴、基线及窄宽变化。相同 Space Token 和 `align-items:center` 不代表实际内容已经对齐。

工具行先列出完整单元及其关系，再决定 DOM 分组。同级单元的可见表面外缘使用一致间距；无表面单元以内容及命中范围核对留白。仅为实现而增加的 wrapper 不建立新的视觉层级，也不得通过继承外层 gap、margin 或 space-between 偶然拉大某一段距离。不同间距必须对应明确的组内/组间关系，并在组合层声明；空间不足时优先按单元换行。

例如分类、搜索与外观切换若是同级浏览工具，应由同一行统一控制间距；分类与搜索的内部 wrapper 不得使用一套 gap，而外观切换又继承 Header 的另一套 gap。确需将外观切换独立成组时，应明确组界及组间距离，而非依赖 DOM 层级产生分离。

- 容器负责共同外缘，子项负责自身内容与命中区域。可见外缘包含容器与首尾子项 padding、必要边缘和图标绘制内距。
- 相邻可见内容距离包含 gap 与两侧子项留白。组内关系须比组间分离更紧，不能因混入按钮而偶然增大距离。
- 图标与说明、动作、标签与字段分别是完整单元。不要把普通说明伪装成按钮，也不要让信息单元依赖相邻按钮的 padding 获得留白。
- 4px inset 的紧凑共同底座要求子项自身已有协调的内容留白；不作为所有工具区的通用 padding。plain 不取消按钮的尺寸与内边距。
- 首尾、纯文字、纯图标、长标签、混合尺寸及换行后的行首行尾都应成立，不为某个 SVG 或截图添加首尾 margin 补丁。

共同工具行中，信息、字段和普通动作单元可消费 padding-control（12px）横向留白与 gap-control（8px）间距；这是该组合的消费约定，不覆盖所有容器与独立控件。有自己轨道的选择器保留内部 inset，不重复增加留白。

### 连续内容与离散对象

正文、列表、数据和设置优先用阅读轴、标题、列关系和必要分隔组织。灰底须说明共同承载范围，不给每个指标、字段或状态自动生成一张卡。

离散作品或独立对象可以有各自表面，但应能说明识别用途。状态优先直接表达，只有需要独立标签识别时才用 Badge。组合按任务分配宽度，不默认把批量栏或一两个配置参数拉满全行。

组件应用按信息角色选择：分类、技术名称及需逐个辨认的状态标签默认使用有底色的 Badge；连续辅助说明使用普通文本。Badge 的 quiet 只在明确需要弱化独立表面时使用，不因信息属于辅助层级就自动去掉底色。tone 表达真实语义，emphasis 表达强调；不能用 quiet 补救环境资源或背景映射错误。

## 文字、图标与信息

界面与正文使用 400；页面、小节、弹层及状态标题使用 500。按钮、标签、数值、计数、选中目录、辅助信息及 strong 动作不自动加重。所有交互状态保持字重与图标描边不变。

界面字体使用 IBM Plex Sans / Sans SC，代码使用 JetBrains Mono；450 资源不消费。字号和行高按角色引用 Token，不逐组件打补丁。当前标签与控件值为 13px / 400，状态标题为 16px / 500。阅读页面按内容安排受限阅读宽度，不能将展示参考中的某个标题尺寸推广成全部 UI 尺寸。

### 正文与文本列表体例

- 普通正文使用 14px / 400，读取 font-size-body 与正文行高资源。
- 有共同背景和内容边距的文本列表使用 13px / 400，读取现有 font-size-control 与正文行高资源；背景、边距和行关系已提供识别层级，不再放大文字。名称与值使用同一字号，通过列关系及语义前景区分，不能把名称当标题加大或加重。
- 属性说明与元数据列表使用 dl / dt / dd；顺序或无序内容使用 ol / ul / li。复用组件应承接对应语义、字号、行留白和分隔职责，不依赖宿主偶然继承的字号。列表内的真实标题、代码及操作仍遵循各自角色，不将整片内容强制为单一文字样式。
- 每份列表共享一个承载范围与内容轴，不给每行另套卡片。名称列和内容列由组合安排，长文本换行，窄宽可转为上下排列；不设固定行高裁切内容。
- 分隔线先确定分割范围：分割完整列表行时由列表承载层负责，横向触达承载区内边界；只分割文字区域时与内容轴对齐并保留缩进。整份列表默认采用同一方式，不由 border 所在 DOM 层级偶然决定。只有确需区分行关系时使用分隔，不以横线充当外壳。

组件库以 `src/ui/typography.tsx` / `typography.css` 统一承接四类文本体例：

| 组件            | 语义与体例                                              | 组合职责                                                            |
| --------------- | ------------------------------------------------------- | ------------------------------------------------------------------- |
| Heading         | level 选择 h1–h6；page 为 22px，section 为 16px，均 500 | 标题层级按文档结构选择，视觉体例独立选择；不由字号反推 h 标签       |
| Text            | p / span；body 为 14px / 400，supporting 为 13px / 400  | 正文与辅助文字不自带表面，保留换行和文本选择                        |
| TextList        | ul / ol 与 li；contained 为 13px，plain 为 14px         | contained 提供共同背景与边距，plain 承接正文列表；保留有序/无序标记 |
| DescriptionList | dl / dt / dd；contained 为 13px，plain 为 14px          | 名称与说明共享列关系；有表面时整行分隔，长文本自适应，窄宽上下排列  |

组件默认不带浏览器的外部 margin，组间距离由宿主按阅读关系安排；列表负责内部留白。文本组件不承担阅读画布、截断、折叠、业务文案或固定宽高。plain 列表不建立额外表面环境；contained 消费现有 Surface 环境，不重复嵌套承载。根节点保留原生属性与 ref。

标题与说明列表使用原生语义，依据 [HTML 标题层级](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/Heading_Elements) 与 [HTML 描述列表](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dl)。

DescriptionList 的 contained 体例保留 13px 文本，行上下留白 16px、左右 20px、列间距 20px；名称列使用 10em，随文本尺度分配，窄宽转上下排列。分隔触达承载区内边界，行高由内容与留白自然形成，不把 padding 随字号机械缩成同一个数值。

以上 13px 规则针对具有共同背景和边距的文本列表；正文中的原生项目列表仍使用 14px 正文体例。

图标使用官方 `@uplus-icon/react`，默认 weight=1、absoluteWeight=true，与所属动作文字共享 currentColor。不复制参考站 SVG、不修改上游 SVG；关闭、展开、增减等结构图标保留语义。图标详情中的显式 weight 比较不构成交互反馈。

Checkbox 的勾是必要的选中标记，在 18px 标记内使用 14px 图标、固定 weight=1.5 与 absoluteWeight=true，保证小尺寸下的辨认。此为状态标记的固定规格，不改变普通动作图标默认重量，也不随 hover 或按压改变。

### 文案与文本选择

组件内容、可选标题、描述、占位提示和数量摘要由宿主提供，省略时不渲染空文字节点。只有必要内置动作可提供可替换的中文功能名称。没有可见 label 仍须有可访问名称，placeholder 不能代替名称。

不默认添加初始化计数、模拟成功消息、执行流水、重复状态旁注、题注或解释组件结构的文案；不能把这些内容移入隐藏 live region 绕过限制。真实错误、进度及无法从内容变化获知的必要结果可独立提示。规范正文负责解释，演示负责呈现；比较对象的辨识标签和必要来源可以保留。

操作文案默认不可选中；输入、正文、代码和可复制结果保留文本选择。不在 Surface、Dialog、Disclosure 或页面根部全局禁用选择。

文字选中高亮的背景与前景须成对适配主题，宿主 `::selection` 使用 action / on-action，保持选中文字可读；不得将固定浅色灰阶背景与随主题变亮的 text 前景组合。

## 交互状态与语义

hover 与按压是临时反馈，selected / checked 是持续状态，focus 表示键盘定位，error 表示真实输入问题。相同状态名不要求不同交互模型使用相同外观。

| 对象或状态       | 执行规则                                                                                         |
| ---------------- | ------------------------------------------------------------------------------------------------ |
| 独立按钮         | 图标与文字同色，前景和背景可共同改变；禁用不响应动作。                                           |
| Disclosure 标题  | 常态与 hover 均透明，hover 只将文字与展开图标前景变为 text；辅助动作独立反馈，不铺矩形背景色块。 |
| 共同动作组       | 底座稳定，反馈限于当前子动作；plain 组不抹去主要动作的表面。                                     |
| Segmented / Tabs | 未选项 hover 文字变深，与选中文字一致；计数保持辅助色；选中项 hover 或重复点击不增加反应。       |
| 选择器持续状态   | 指示块平滑移动并改变宽度，无回弹；换行同步几何，文字与图标重量保持不变。                         |
| 输入焦点         | 仅 Tab 定位显示轻量提示；鼠标点入与正常输入不启用外圈，保留真实焦点、光标及键盘语义。            |
| 非文本操作焦点   | 使用可辨认的 focus-visible，不能以软边界为由删除提示。                                           |

Tabs 保持 tablist / tab / tabpanel 内容切换语义；Segmented 保持 radiogroup / radio 值选择语义。共享外观不互换语义。只在 hover 出现的必要操作，还必须满足键盘与触屏访问。

字段优先原生语义和属性，Field 管理标签、提示、错误关联。Select 使用 Radix 无样式基础处理定位与焦点，不重复实现菜单行为。原生 Dialog 内的 Select 菜单挂载到所属 Dialog，保持顶层可见与可交互；普通页面仍挂载到 body。开关、数值、弹层与异步动作的受控状态、ref 及回调依照 [API 名单](api-contract.md)，不另建第二份接口表。

### 可执行的验收条件

- 普通正文、辅助文字、占位提示与操作文字的前景/实际底色对比至少为 4.5:1；24px 及以上文字至少为 3:1。禁用内容和纯装饰不套用文字阈值。依据 [WCAG 文字对比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)；这是执行目标，不是所有现有组合已经通过的声明。
- 对辨认必要操作、选中、错误和焦点不可或缺的非文字标记，与相邻颜色至少为 3:1。只有文字即可辨认的控件，不为凑比例强加常驻轮廓；必须辨认的状态不能只依赖柔和表面色差。依据 [非文字对比](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。
- 默认独立操作命中范围至少为 24 × 24 CSS px；视觉标记小于命中范围时，依靠关联 label 或实际点击区域满足。行内链接、原生控件及通过间距满足条件的例外按 [最小目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)判断，不扩大绘制图标替代命中检查。
- 组合评审覆盖亮/暗环境、320px 窄宽、200% 缩放、长中文与无空格文本、键盘顺序和触屏必要操作；低高度视口检查内容与关闭入口能否到达。对比、真实命中和缩放由实际消费场景确认，静态几何检查不代替这些证据。
- forced-colors 使用系统色保持自绘标记、选中与焦点；必要标记可局部保留系统色绘制，不在整个界面禁用系统颜色调整。等待状态在减少动态效果时仍保留文字或可访问名称。

## 动效语言

### 目的与判断顺序

动效须符合操作预期，让用户明白发生了什么交互，呈现自然、优雅。先判断事件、状态与对象关系，再选择运动方式；不能先套动画模板，再寻找用途。以下规则按交互角色组织，适用于未来组件；示例只解释规则，不构成逐组件专属指令。

设计顺序为：**触发事件 → 真实状态与操作资格 → 用户需要理解的信息 → 变化对象与稳定参照 → 协调过渡 → 中断与回撤 → 减少动态效果。** 没有需要解释的变化可以直接发生。结果本身清楚时，不额外增加确认提示或强调动画。

### 状态与反馈职责

状态按相互独立的维度建模，不强制排列成 default → hover → pressed → selected 的单一流程。焦点可与选中、hover 或等待并存；每种反馈只承担自己的信息职责。

| 维度       | 需要表达的信息               | 执行原则                                                                                                                      |
| ---------- | ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 操作反馈   | 可操作、正在按压、释放或取消 | 及时响应实际输入；临时反馈可撤回，不提前表达成功。按钮式动作与导航具有按下去的缩放触感，底层使用 button 或 a 不改变反馈契约。 |
| 持续状态   | 选中、展开、不可用           | 状态保留到真实改变；不能靠重复播放动画维持识别。选中项重复操作不增加无意义反应。                                              |
| 定位与校验 | 焦点在哪里、哪里需要处理     | 焦点独立可辨；错误使用明确的文字与状态表达，不默认抖动，不通过运动取代说明。                                                  |
| 任务状态   | 等待、进度、成功、失败       | 反馈真实任务；不人为延长等待、不模拟成功。结果难以感知时才增加必要确认。限制重复执行来自业务约束，不来自动画时长。            |
| 直接操控   | 对象跟随当前操作             | 拖动、滑动、输入与连续数值变化即时跟手，不加入造成追赶感的自动补间。释放后的归位或吸附依据任务契约。                          |

共享行为通过共享实现维护，不能只复用颜色与几何，遗漏按压、取消、禁用或减少动态效果。同类按钮式操作在独立与成组场景保持触感；仅当前项缩放，底座与相邻项稳定。不可用、禁用与 busy 操作不产生可执行的按压反馈。文本链接、选择指示块等其他角色不自动套用按钮缩放。

### 状态时序与操作权

操作成立后，逻辑状态、回调和有效操作目标及时更新，视觉解释这次变化，不等待动画完成。进入中的有效对象可以操作；退出中的旧内容立即 inert、从可访问树和交互命中中退出，即使暂时仍可见。旧内容不能遮挡或接收新目标的操作。

焦点随有效界面协调转移。折叠或关闭包含焦点的内容时，将焦点交还有效入口或按任务约定转移。模态退出期间可以保留原生 top layer 与背景隔离，直到窗口离场；窗口正文不再可操作，焦点及背景操作权在实际关闭时恢复。非模态内容不能因退场占用新任务的操作权。不能为退出动画延长 live region 播报或重复读出旧内容。

### 中断、撤回与连续性

动效始终响应最新意图，从当前呈现转向最新目标。快速反向不跳回起点、不先播完旧动作、不排队、不用计时锁禁止操作。位置、尺寸、透明度等可见属性保持连续；直接操控优先跟手，自动过渡平顺转向，不为保留惯性而违背新目标。默认不回弹或过冲。

取消按压与取消拖动撤回临时反馈；改变选择或展开目标转向新状态；已提交业务是否能撤销由业务能力决定，视觉回撤不能假装撤销保存、删除或发送。完成回调只完成最新目标的清理，过期回调不得关闭重新打开的对象、恢复旧状态或移走当前焦点。

### 对象关系与运动选择

| 关系               | 设计规则与示例                                                                                                             |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| 同一对象改变形态   | 外壳尺寸与必要位置连续变化；文字、图标保持尺度，不随父级拉伸。按钮文案改变时，宽度与内容交接协调进行。                     |
| 标记转移目标       | 指示块按实际目标的位置与尺寸移动，稳定参照保持不动；不硬编码标签宽度。                                                     |
| 所属空间展开、收回 | 空间尺寸与内容透明度协调变化，入口与内容关系连续；只淡入内容而瞬间跳开布局不符合此规则。                                   |
| 浮起对象出现、退出 | 渐入并轻微上升，退出更快地渐出并回落；遮罩协调淡化，不跟随位移或缩放。                                                     |
| 锚定对象出现、退出 | 根据入口与实际定位方向短距离进入，朝入口收回；定位翻转时方向随实际位置调整，不统一从下方进入。                             |
| 边缘对象进出       | 沿所属边缘运动并淡化，例如侧边抽屉；不套用居中浮窗的上升方式。                                                             |
| 内容替换           | 短文本优先轻微模糊与淡化交接；普通内容面板短暂淡化，不默认滑动、模糊正文或把无关内容强行形变。明确顺序才使用方向表达顺序。 |

### 多维编排与阅读保护

同一次变化涉及内容、尺寸及必要位置时协调开始与收束；同步不要求所有属性使用相同曲线或时长。控制影响范围，只让解释关系所需的对象运动；尺寸变化确实影响邻项时才让邻项同步移动，不让整页参与局部反馈。

短内容交接采用**退出快、进入稍慢、轻微重叠、尺寸同步**：旧内容淡出并变模糊，新内容在旧内容消失前从轻微模糊中变清晰，不出现空白停顿。旧内容不参与正常排版、不影响目标尺寸、不重复进入可访问名称；最新内容决定布局与语义。快速连续替换不排队，过期视觉层及时清理，不持续堆叠重影。

模糊只用于必要的短内容交接，不用于输入中的文字、直接调节的连续数值、长正文或所有浮层。禁止拉伸文字、动画改变字重、交接时两份内容共同撑宽容器。固定宽度对象保留任务需要的宽度；内容变化不要求强制变宽。

### 节奏与共享参数

退出及时让出注意力，进入稍舒缓；直接操控即时响应，按压迅速建立触感。以下是首轮实现基线，服务语义角色而非逐组件选参；观感仍须实际校准，不能用静态检查宣称自然或优雅。

| 用途                     | 初始基线                                                          |
| ------------------------ | ----------------------------------------------------------------- |
| 颜色反馈                 | 150ms，ease-out                                                   |
| 按压 / 释放              | 80ms / 150ms，ease-out；按钮式操作 scale 0.97                     |
| 进入 / 退出              | 240ms / 140ms；进入使用 ease，退出使用 ease-in                    |
| 连续布局与标记移动       | 240ms，ease，无回弹                                               |
| 短内容交接               | 进入 240ms、退出 140ms，同时开始形成有限重叠，模糊最大 4px        |
| 短距离空间运动           | 浮起 8px、边缘 20px、锚定 4px，依据关系选择，不随对象体积任意放大 |
| 减少动态效果下的必要淡化 | 至多 100ms；空间变化与按压直接呈现                                |

共享 ease 为 cubic-bezier(0.23, 1, 0.32, 1)，退出 ease-in 为 cubic-bezier(0.4, 0, 1, 1)。各属性可以分别选择布局、进入或退出节奏，不为单件随意新增时长、曲线、回弹或幅度。CSS 颜色与按压读取共享 Token；布局、内容与空间变化使用现有 Framer Motion，共享配置集中在 `src/ui/motion.tsx`；工程映射见 [Token 文档](tokens.md#动效与工程入口)。不新增动效依赖。

### 生命周期与减少动态效果

页面初次渲染不统一播放入场；用户触发的新对象和后续动态新增对象按用途进入。稳定对象的内容更新不通过重挂整个对象制造入场，不能丢失输入值、焦点或滚动位置。

减少动态效果时取消位移、缩放、模糊及尺寸补间，立即呈现最新几何与清晰内容；必要短暂淡化可以保留。等待保留静态标记、文字或可访问名称，必要状态不能只靠旋转表达。依据 [W3C 交互动效说明](https://www.w3.org/WAI/WCAG21/Understanding/animation-from-interactions)。

窗口持续调整、任意外部 CSS 变化不属于自动布局补间保证；不增加通用观察器兜底。退出生命周期使用当前目标与取消机制管理，Motion 工程依据见 [动画](https://motion.dev/docs/react-animation)与 [AnimatePresence](https://motion.dev/docs/react-animate-presence)，实现能力不能反过来替代设计判断。

### 开发与验收契约

每个交互单元记录事件、并存状态、真实目标、反馈信息、变化属性、稳定参照、操作资格与焦点、进入/退出节奏、中断与减少动态效果。新增组件先匹配上述角色；有新关系再补主规范，不要求新增逐组件动画指令。

定向验收覆盖正常触发、按下取消、快速反向、连续替换、禁用 / busy、退出操作隔离、过期完成回调、初次呈现和减少动态效果。检查语义、状态与生命周期，源码时长相同不等于完整动效合规。浏览器与光学体验核查仍需用户授权；未核实的观感如实保留为验证边界。

## 组件与组合契约

基础组件负责语义、状态与操作能力；组合组件负责共同范围、排列和尺寸协调；页面负责任务、阅读顺序、主次与出现时机。颜色上下文不替代这三个层面的判断。

公共内容统一通过 children 与语义子组件组合进入，目标名单和迁移状态见 [API 规范](api-contract.md)。父组件负责表面、padding 和整体动效，子组件负责区域排布与语义关联，不重复叠加父级承载。内容接口迁移不自行改变已确认的视觉契约。

| 场景                     | 契约                                                                                                                                                     |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 操作组与批量栏           | 只组合相关任务；SelectionBar 不拥有业务选中集合，数量摘要由宿主提供，不默认固定定位或铺满页面。                                                          |
| 连续调节工具             | 标签、轨道、数值和对应重置沿同一操作轴；宿主分配可伸缩轨道，必要分隔区分调节与重置，窄宽按完整任务组调整。                                               |
| Disclosure 与用法        | 标题为透明控制，复制等辅助动作是同级元素，不能嵌入展开按钮；正文直接呈现，不再套一张内容卡。                                                             |
| 展开长文                 | 独立 ExpandableCode 保留内容渐隐与展开职责；不与用法 Disclosure 叠加第二套展开机制。                                                                     |
| 展示卡与导航卡           | 内容名称依附对象，hover 出现不自动等于独立浮层；独立外链与主导航使用兄弟节点，不嵌套链接。触屏仍需可辨认名称。                                           |
| 模态与抽屉               | 共享生命周期、焦点与关闭契约；busy 和不可关闭状态表达真实任务限制，宿主管理请求结果。                                                                    |
| ColorPicker              | 保持单件选色面板，由宿主决定是否置于弹层；彩色渐变表达真实颜色，数值字段使用统一控件尺度，不重复套卡。详细行为见 [组件契约](color-picker.md)。           |
| Toast、Alert 与 Progress | 只报告真实状态，前景和底色按 tone 配对；宿主管理业务结果、提示队列与进度含义。单独的 Toast 固定在视口底部。放进 ToastRegion 后由区域统一停靠并纵向排列。 |
| 进行中                   | Spinner 表示真实等待。Button 的 `busy` 使用同一转圈标记，保留按钮文字，并挡住再次触发；它不套用 disabled 的褪色。减少动态效果时停止旋转，状态仍可见。    |

代码与 Disclosure 读取 region 并组织标题、复制与正文。分隔线依据阅读结构决定，不作为默认外壳；有标题/正文分隔线时复制使用 quiet，无分隔线时按操作识别需求选择 quiet 或 default。

ToastRegion 以视口高度扣除上下留白限制范围，只有提示的布局高度超出时才在区域内滚动；进入、退出和重排位移不打开滚动条。区域可键盘定位，单条提示不被压缩，长文字换行且保留关闭入口。宿主仍负责队列上限和业务优先级。Toast 的自动关闭只在打开、时长或暂停状态改变时重新计时；更新文字或回调不延长期限。悬停/焦点暂停，离开后重新计满配置时长。新通知需要新实例或一次关闭/打开，不能依靠无关重渲染续期。

教学示例的关闭、重开和计时必须真正影响示例状态；预览与复制代码采用同一交互模型。纯类型正确或空回调不构成完整示例。

## 展示与设计实践

展示站保留规范、Token、单件组件、API 配置及生成用法，不恢复公开案例页。内部 `lab/` 参考成熟产品的信息架构，以本系统组件搭建完整任务原型，页面不放调试开关；差距记录留在开发文档中，源码随 Git 维护，仅通过独立本机入口运行，不部署；它不是公开展示内容。规范页以正文和对应演示解释规则，不套组件详情的整套配置模板；教学示例默认直接使用灰色承载。演示宿主的观察空间不成为通用组件最低高度。

组件详情的名称保留在 Preview 外；“预览”、环境切换与 API 收起/展开位于容器内部顶部。实例与配置属于一个任务，配置放在实例下方并使用完整宽度，按内容自然展开，不设内部滚动。配置顶部提供预设 / 自定义切换；预设是完整组合，其选择入口不与真实参数混排。自定义区直接呈现常用参数及 children 节点列表，详细属性、添加节点与嵌套 children 在现有 Dialog 中编辑，内部节点沿同一个编辑窗口前进与返回。界面只呈现操作名称、真实参数名、当前内容与必要的状态或错误，不展示类型、默认值、签名、规则元信息或解释性文案，也不将其转移到提示浮层。普通参数多栏排列，名称在编辑对象上方；节点入口呈现简洁摘要，编辑、删除与允许的排序使用同级动作，参数和节点不各自套卡片。tone 使用环境语义色样，配对读取底色与前景，选中标记和名称保证不只依赖颜色识别；emphasis 与 size 使用实际强调和尺度样本。图标复用可搜索的完整预览选择。色样和普通编辑入口采用 36px / 12px 的控件几何，不添加无用途共同底座；节点入口与相邻操作按任务换行，不压缩控件。“重置示例”使用灰底，恢复当前完整预设，不冒充组件默认值；“用法”默认收起。

环境切换只影响实例承载，不改变组件属性、代码或重置范围。预览状态、配置与代码同步，编辑器只使用本系统组件；调试实现不进入组件包。响应式栏宽、数组草稿和代码生成等工程细节见 [playground.md](playground.md)。

滚动由工作台目录和内容区域承担；实际需要内部滚动的字段、弹层与代码区使用统一滚动契约。占位式滚动条预留稳定空间，不能靠全局禁止滚动或裁切内容修复宽度跳变。

## 开发、评审与维护

1. **说明任务与关系。** 列出必要内容、状态、操作及宿主宽度；先判断信息、对象与空间，不从容器外观开始。
2. **选择现有契约。** 按对象角色确定环境、边界、几何与交互。查看 API 名单和实际导出，不为示例新增组件属性或复制一套控件。
3. **实现完整组合。** 使用现有 Token、原生语义与组件组合；CSS 与 Motion 共享几何来源，保持原生属性、ref 和焦点职责。简单需求不新增依赖。
4. **定向核查。** 检查相关亮暗环境、独立与成组、长内容与窄宽、必要状态和键盘语义。按改动运行类型检查与必要交互测试；纯文档不运行构建或测试。浏览器与大规模兜底验证须先获用户同意。
5. **更新唯一规则。** 新决策写入本文对应章节，同步工程映射、组件与必要示例。未确认项放入待讨论段落，不追加新的平行规范；只声明实际完成的验证。

新增外观检查真实必要性、与已有规则的一致性、组合与环境适配、可预测行为、可用性及维护成本。路线图不授权实施全部候选。组件库的构建、消费与发布另遵工程文档，不把设计规范变成部署授权。

仓库配套 [uagray-generate](../.agents/skills/uagray-generate/SKILL.md) 与 [uagray-check](../.agents/skills/uagray-check/SKILL.md)，分别服务组件/页面生成与设计实现检查。Skill 引用本文，只维护工作流程，不复制色值、尺度或另写设计规则。

`npm run check:design` 运行 [源码检查器](../scripts/check-design.mjs)，`-- --json` 输出可定位的结构化结果。脚本核查已登记的按钮、图标、动作组、选择轨道、菜单、取色面板和 Preview 的几何关系，以及 CSS/Motion 圆角与时长、预览工具栏尺寸、交互字重和渐隐表面。它只计算显式基础声明，不运行浏览器，不模拟完整 CSS 级联、媒体查询、宿主覆盖或光学布局；新组合须登记，未覆盖项不能视为通过。检查器修改后运行 `npm run test:design`，用已知错误的回归场景验证检测能力。
