## 讨论 01：灰色操作组中的白色选中项

状态：参考站的文字、hover 与滑块触发行为已确认；尚未确定 Uagray 采用范围。

### 用户对讨论方式的要求

### 本轮参考

[搜索与分段截图](../anish-lab/controls-search-segmented.png)。截图可见：分段有共同灰色底座，当前项为白色并有浅边缘；未选中项没有各自的独立底块。截图无法确认 hover 的处理。

### 助手提问

先只看这个分段控件：在共同灰色底座里，未选中项平时保持透明，白色用于当前项。你认为这个处理应成为“互斥选项组”的默认规则吗？如果你观察过原站，未选中项 hover 时是否会出现单独的底色，它与当前项的白色有什么区别？

### 用户回答

> Segmentedhover时候，改变的只有hover项的文字颜色，并且这个值和选中白底时候的值是一致的，也就是说，item的文字颜色有两种状态，深浅，深色的时候就是hover或者选，浅色就是常态，并且动作就是后面的滑块自己跟着动改变底色

### 助手小结

用户确认 Segmented 的文字只有两档：常态浅色；hover 或选中为相同深色。hover 只改变当前项的文字，不新增该项的独立背景。白色选中背景由后方滑块表达，滑块移动承接选中位置的变化，不能将其拆成各按钮独立的 hover 填色。

不补写确切色值、移动时长、缓动、描边或阴影。此结论目前仅针对参考站 Segmented，不自动推广为普通 Button 或其他控件规则。

用户随后确认：滑块只在选中项改变时移动；仅 hover 时，滑块仍留在当前选中项。

### 已确认的参考行为

| 状态           | 文字                    | 背景处理                   |
| -------------- | ----------------------- | -------------------------- |
| 普通未选中项   | 浅色                    | 不新增独立底色，共享组底座 |
| hover 未选中项 | 深色，与选中文字同值    | hover 只改文字             |
| 当前选中项     | 深色，与 hover 文字同值 | 后方白色滑块表达选中位置   |

以上是用户确认的参考行为，是否作为 Uagray 契约尚待本议题讨论完成。

### 回答 04：滑块边缘、点击、移动与计数

用户：

> 滑块是带有浅色描边和轻阴影，hover选中项无反应；点击选中项无反应，点击其他项只有背景色块跟着走的效果；滑块宽度是平滑移动，没有回弹；常态标签和计数平时是同一个浅色，计数在标签变深后也不变色

助手小结：白色滑块的浅色描边和轻阴影是稳定外观；hover/点击当前选中项不额外改变外观。点击其他项改变选中位置，背景滑块平滑移动并适配宽度，无回弹或额外缩放/压下效果。常态标签与计数同浅色；只有标签在 hover/选中时变深，计数保持原浅色。未从回答推断具体色值、线宽、阴影参数、动画时长或文字切色的过渡方式。

## 问答 26：选择器一致性、白色分离与案例碎片化

**用户：**Tabs 与 Segmented 的视觉和动效不一致，灰底缺失，很多白底没有描边/阴影；要求补齐契约并改善案例，特别是 SaaS 一块内容一块灰底的问题。

**原因：**Tabs 用选项自身换色，Segmented 用移动滑块，两套几何各自实现；灰 Surface 自动反转选择颜色；白工具层依赖页面局部补阴影；案例指标、表格和设置按组件块套 Surface/Disclosure。

**实施：**共享选择滑块测量、无回弹过渡与反馈样式，保持 Tabs 与 radio 的语义差异，重复点击当前项不重复回调。选择底座与滑块拥有自己的颜色关系。独立白工具层集中使用同一边缘/轻阴影 token，普通内容不自动浮起；漏掉灰承载的布局演示补齐。SaaS 指标、表格与设置回到页面阅读轴，保留控件底色、列对齐和必要行分隔；海报编辑正文移出灰折叠块。工作台和图像承载范围保留。

验证：类型检查通过；43 个相关定向测试通过（其中一项旧文案断言随规则正文同步更新）。未使用浏览器，不能将此视为视觉与动效验收。
