# 灰底表面、组合与阅读实施契约

2026-10-10 用户确认。本契约落实 P03–P09，不新增核心原则；与旧稿的外观提案或实施记录冲突时，以本契约为准。本轮已按契约对齐相关源码；源码和 DOM 检查不代表实际视觉已经验收。

## 灰底上的三种常态表面

以下讨论组件的背景填充，不限制文本、图标或图像本身的颜色。灰色承载上，普通 UI 的常态表面只有三类：

| 表面     | 职责                                         | 使用条件                                                           | 不允许的替代方式                                         |
| -------- | -------------------------------------------- | ------------------------------------------------------------------ | -------------------------------------------------------- |
| 透明     | 共享已有承载，保持内容连续                   | 普通文字、清楚可辨的 Ghost 动作、已有共同边界中的附属操作          | 用透明掩盖操作不可辨认或内容没有组织的问题               |
| 深一级灰 | 轻量区分内部单元或局部状态                   | 需要常驻范围，但不需要白色独立对象强调的 Badge、局部操作、内部单元 | 同色灰填充、不断加深的灰阶嵌套、用描边补救灰色对象       |
| 白色     | 建立独立对象或操作范围，提供更明显的局部对比 | 独立编辑区域、需要分离的工具或内容对象、确有强调职责的操作         | 因父级是灰底就把所有子项翻白，或给整段展示内容重复套白壳 |

浅色环境中区域灰为 surface、深一级灰为 control、白色为 raised；这里只定义资源角色，不授权新的任意灰阶。深色主题按相同职责映射主题资源，不机械使用字面纯白或把原始色值取反。

交互时允许局部改变前景或背景，但 hover、选中、错误、键盘焦点必须分别表达。可识别性应在常态成立，不能依赖 hover 才知道哪个是操作。

## 表面选择评判顺序

1. **确定任务与对象。** 指明这是阅读内容、输入字段、动作、状态标记、独立内容对象还是成组工具；明确动作作用于什么，结果显示在哪里。
2. **确定已有组织。** 检查标题、阅读轴、主次关系、间距、分隔与共同边界是否已说明归属。没有组织时先组织，不用背景替代信息结构。
3. **先判断透明是否充分。** 内容归属明确、操作在常态可辨且父级已承担范围时，采用透明。不能仅以有标签或有点击事件作为通过依据。
4. **判断是否需要常驻局部范围。** 需要区分单元或状态，且无需独立对象强调时，采用深一级灰；检查轮廓与前景是否能在父级灰上辨认。
5. **判断是否需要独立对象对比。** 编辑范围、工具范围或内容对象需要独立识别，深一级灰不足或与任务的视觉优先级不符时，采用白色。白色不是所有灰底控件的默认答案。
6. **独立审查边缘。** 只有白底且具有明确强调或分离职责的对象才允许常驻描边；填充已经充分时仍应省略描边。灰底不通过加轮廓线补救。
7. **审查完整组合。** 同时看父级、子项、状态、正常/交互表现、长内容、窄容器和主题。共享 token 或单件看得清不能替代组合判断。

每个判断记录：任务对象、已有共同边界、需要辨认的范围、选择的表面、tone、状态反馈、边缘职责。相同职责和环境采用相同策略；不能用组件名字代替这些判断。

## tone 与 Badge

neutral / success / danger 等 tone 必须同时适配表面与前景，不把浅页面上的浅色状态底直接搬到灰区域。tone 表达语义，不增加第四种表面角色。

- 透明状态：使用可辨的语义前景，依靠文字或图标说明状态，不生成独立背景。
- 深一级灰状态：中性使用 control；有色 tone 使用相对当前灰底具有同等级可辨区分的语义色底，并与对应前景成对定义。不能仅将文字染色、背景仍与父级几乎融合，也不能增加字重补救。
- 白色状态：只有状态需要独立标签或局部强调时才使用 raised，语义前景保持对应 tone。不是灰底 Badge 一律翻白。

检查文字可读性、标签范围、相邻状态的区分、禁用与主题适配；颜色不能成为唯一的语义线索。不在本轮凭空确定新 tone 色值，具体 token 配对待实施时校准。

## 成组组件的整体判断

先决定整个组的任务范围与共同表面，再决定各子项的常态、hover 和选中范围。

- 父级已有明确工具或阅读边界：组可透明，附属动作常态透明，不逐按钮铺底。
- 独立操作组需要共同范围：整体选择深一级灰或白色；普通子动作共享底座，仅当前项获得局部反馈。
- 字段、持续选择、错误与结果有各自职责，不能为了组内统一全部透明，也不能给每项独立强调。
- Tabs / Segmented 的轨道与指示块按选择整体审查；灰底上直接使用深一级灰轨道与白色选中块，不自动再包白色工具外壳，也不加常驻描边补救。同色融合先修正轨道对比，不制造第二层容器。
- 内外留白与圆角按等距契约协调，但不得为了同心关系增加容器。

## 教学示例的组织

灰底负责教学展示承载；示例必须真实呈现所讲的关系，明确对象、动作与结果，不能把若干文字、Badge 和按钮堆在中间作为完成证据。

对象内部可以按任务建立白色面板或深一级灰单元，但不能统一加整块白色画布。图片与名称、步骤与图解可以形成完整单元；居中与否由内容性质决定。表面比较必须存在实际可辨的环境或对象差异。

每个示例拥有自己的状态与反馈，反馈只出现在对应任务中；不同示例不得共享一条业务 message 或计数。必要的内容标识可以保留，不能通过堆重复解释文案弥补示例结构。

## 文本体例与 Disclosure

撤销“单一白色阅读边界”。代码、用法和类似文本体例在浅页面上优先使用灰色阅读承载；折叠能力本身不赋予白底、常驻描边或分隔线。

Disclosure 按完整阅读单元判断：标题、复制动作与正文具有共同归属。标题是透明控制，复制与标题为同级元素，不嵌套按钮；代码直接呈现，保留一套折叠机制，不给正文再套一层卡片。

| 灰色阅读组合                 | 标题与正文                           | Copy 常态                            | Copy 交互                |
| ---------------------------- | ------------------------------------ | ------------------------------------ | ------------------------ |
| 有必要的 head/content 分隔线 | 共享灰底，仅用一条内部分隔明确两部分 | 必须透明                             | 局部反馈，不新增常驻表面 |
| 无 head/content 分隔线       | 用留白、对齐组织共同阅读             | 可透明；若操作识别不足，可用深一级灰 | 与所选常态表面配套反馈   |

分隔线是否存在由阅读结构决定，不能从代码块参考自动推广为所有 Disclosure 的默认值。灰色阅读组合中的辅助 Copy 不使用白色独立强调。普通连续折叠正文不强制新增灰卡；作为灰底中的独立对象展示时，按对象职责重新判断透明、深一级灰或白色。

独立 ExpandableCode 同样遵循文本体例契约，不因自身有展开操作而获得白色外壳或独立灰按钮。CopyButton 提供 soft / plain 组合入口；用法有分隔线时显式采用 plain。

## 常驻描边硬性规则

**常驻对象描边只允许用于白底且具有明确强调或分离职责的对象。白底是必要条件，不是自动加描边的理由。**

灰底、深一级灰或透明对象不得使用常驻轮廓描边，包括借 border-block、inset shadow 或伪元素模拟轮廓。白色选中块、白色定义工具区等也必须说明强调或分离职责，不能仅因某个 treatment 名称自动通过。

内容分隔线只表达内容之间的结构，不围合控件，不沿圆角形成近似封闭轮廓；不能把上下边线称为分隔来绕过规则。focus、错误等按交互或真实状态出现的提示不属于常态装饰描边，仍须有可辨的语义和退出条件。

深色主题中“白底”对应浅色主题白表面的语义角色 raised，并遵守同样的强调条件；不据当前明暗值任意豁免灰色表面。

## 实施状态

已更新灰环境 tone 配对、Badge 的 soft/plain/white 入口、Disclosure 与文本体例、CopyButton 的透明组合入口、Surface 描边限制和教学示例的组织与状态隔离。灰底中的选择器直接使用深一级灰轨道与白色指示块，已撤销自动增加的白色外工具层。灰色选择标记与上传范围不再使用常驻描边。类型检查与相关 DOM 测试通过；实际色差、圆角和动画尚未进行浏览器验收。

## 冗余演示信息禁令

基础组件与规范页示例不得默认添加初始化计数、执行流水、模拟成功消息、重复状态旁注或解释自身结构的文案。例如“已添加 0 项”“编辑已打开”不能作为通用演示模板；也不能移到隐藏 live region 规避禁令。

只有真实任务必须知道且无法从控件/内容变化获知的结果、错误、异步进度或必要的无障碍反馈才允许独立提示。选择通过选中状态表达，编辑通过实际字段表达，数量通过实际内容表达。演示没有对应业务任务时，只展示必要的控件反馈，不附带模拟业务状态。

教学图示中的“信息/对象/空间”“白底/灰底”等辨识标签用于区分比较对象，可以保留；它们不属于模板状态提示。

组件文案由宿主提供：可选标题、说明、占位提示、数量摘要和进度旁注默认省略，未提供时不渲染空文字容器。不得把演示文案写入组件默认值。Alert 的 title、Field 的 hint/error、Dialog/ConfirmDialog 的 description 按需传入；SelectionBar 用 summary 提供摘要，count/total 仅服务操作状态；Progress 用 label/valueLabel 提供标题与进度文案；FileDropzone 的 label 为可选说明，buttonLabel 为选择动作名称；NavigationCard 用 directionLabel 提供可选方向文字。SearchField 和 Select 不自动生成 placeholder。展示页与生成代码遵守同一默认值。

保留必要动作名称、内容本体、真实失败反馈和可访问名称。没有可见说明时仍必须能识别控件；不得为了清理文字删除真实输入标签、错误或忙碌状态语义。调用方需要额外业务反馈时，通过已有文案属性、children/actions 等插槽及回调组合。

## 透明动作组与操作优先级

plain 组只提供排列和功能归属，不清空内部按钮的表面。融合子动作常态表面仅适用于已有共同底座的 surfaced 组。编辑表单的主要保存动作保留独立识别，重置等附属动作可透明；不能以成组为由把主要动作也变成文字。

明确操作强调允许按 P09 使用 Dark；这是有职责的强调资源，不扩展普通灰底对象的三类背景表面。规范页使用黑色提交、深一级灰预览、透明取消对照，不附带无关选择字段或模拟结果。
