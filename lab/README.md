# 内部产品原型

这里按成熟产品的页面架构与真实任务，使用 Uagray 组件搭建可操作的页面。当前完成四题：**Linear 项目任务页、anish’s lab 目录 / 详情、GitHub Issues、Vercel 项目设置**。每题直接呈现可操作的产品页面，不出现调试参数或测试开关。

入口按页面分开：

- `/prototypes/`：选题目录，可以进入四个原型。
- `/`：Atlas 项目工作空间，保留原入口。
- `/anish/`：Fieldnotes 作品与工具展厅。
- `/anish/#/piece/palette`：可直接打开具体作品，例如调色工作室。
- `/github/`：Forge 仓库问题管理；`/github/#/issues/284` 直接进入问题详情。
- `/vercel/`：Launch 项目配置管理。

在仓库根目录运行 `npm run dev:lab`，默认地址 http://127.0.0.1:5174；端口占用时自动选择后续端口，以终端的 Local 地址为准。沿用旧实验室地址时，刷新即可进入新原型，旧 URL hash 参数已不再使用。

## 第一题：项目工作空间

- 项目导航：客户门户 2.0、移动端体验、我的任务、所有任务。
- 项目页：任务列表与概览切换，概览包括项目属性、里程碑和由实际任务计算的进度。
- 任务列表：搜索名称、编号或描述；按状态和负责人筛选；按状态分组或查看平铺列表。
- 批量操作：选中任务后全选当前结果、标记完成、分配给自己、确认删除。筛选与视图切换清空选择，避免误操作隐藏任务。
- 新建和编辑：标题校验、描述、状态、优先级、负责人、标签、项目、里程碑和日期。切换项目同步重置为该项目的有效里程碑。
- 讨论：任务详情内添加评论；保存任务属性不覆盖新添加的评论。
- 外观：账户旁的主题按钮切换浅深外观；窄屏可展开导航，列表属性换行。

任务与评论保存到当前浏览器的 `uagray-project-prototype-v1` 本地存储；主题另存。不连接真实 Linear、账号或外部 API。取消任务编辑丢弃未保存的属性修改，评论发送后独立保存。重新载入保持任务数据；要恢复示例，可在浏览器开发工具中删除该存储键后刷新。存储不可用时页面提示当前更改可能在刷新后丢失。

## 第二题：作品与工具展厅

参考 anish’s lab 的信息架构，使用虚构的 Fieldnotes 目录与六个作品：进度面板、阅读便笺、调色工作室、专注计时、成员名片和发布清单。

首页提供分类、搜索、同步计数和错落的作品网格；详情提供独立交互区、标题与说明、使用组件、补充预览、资料行、分享链接、前后作品导航。搜索与分类在详情往返时保留，切换作品时重置当前作品状态。计时器离开详情时停止，工具内容只存在当前页面会话中；主题保存在本机。预览由静态 HTML 和语义资源组成，不加载原站图像、标识、作品或字体。

## 第三题：仓库问题管理

Forge 的虚构仓库 `atlas / portal-kit` 提供问题列表、详情、标签、里程碑和 Readme。支持状态、标签与负责人筛选，基础查询限定符、排序、当前结果选择与批量关闭 / 重开。新建问题校验标题；详情可编辑正文和属性、发送评论与修改状态。问题详情使用 hash 路由，可直接访问并随浏览器历史返回。

问题与评论保存到 `uagray-issues-prototype-v1`。筛选变化清空选择；取消正文编辑恢复已保存内容；负责人、标签和里程碑独立保存。标签与里程碑页提供目录和进入相关问题的入口，不实现仓库级配置编辑。

## 第四题：项目配置管理

Launch 提供常规、构建与输出、环境变量、部署保护四个配置分区。名称、根目录与构建设置分别保存；关闭构建覆盖恢复框架预设。环境变量支持搜索、环境筛选、显隐、新增、编辑和确认删除；同名变量可以属于不同环境，重叠环境禁止重复。转移项目保留配置，删除项目要求输入准确名称，并清空变量；删除后可重新创建示例项目。

项目配置保存到 `uagray-launch-prototype-v1`。切换分区丢弃未保存草稿；保存后的设置刷新仍保留。环境变量仅使用虚构值，显隐只是显示控制，本机存储并不加密。页面没有构建执行、部署或真实账号操作。存储失败显示实际错误提示。

## 选题与差距

[Linear 项目任务页：参考、实现与差距](linear-project.md) 记录参考来源、组件映射、已确认的能力缺口和待体验核查项。[anish’s lab 信息架构实践](anish-gallery.md) 记录第二题的结构映射与验证边界。[GitHub Issues 实践](github-issues.md) 与 [Vercel 项目设置实践](vercel-settings.md) 记录另外两题。四份记录是选题实践文档，不定义另一套设计规则；组件设计仍遵守仓库主规范。

源码随 Git 保存，不部署、不进入 npm 包。`vite.lab.config.ts` 仅监听本机并拒绝构建。后续新题使用各自独立的页面入口与业务数据；不在产品原型里套回调试台。

验证使用 `npm run test:lab`、`npm run check`；修改设计检查器后运行 `npm run test:design`。定向交互测试使用 jsdom 的 dialog、测量等适配，不能替代真实浏览器的焦点、视觉和响应式验收。浏览器验收仍需用户授权。
