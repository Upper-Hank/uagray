# 第一题：Linear 项目任务页

## 参考与边界

参考 [Projects](https://linear.app/docs/projects)、[Issues](https://linear.app/docs/creating-issues)、[Issue properties](https://linear.app/docs/issue-properties-home) 的公开产品说明：项目关联任务与里程碑，项目提供概览和任务入口；任务具备标题、状态、优先级、负责人等属性，以及创建和编辑流程。

这些来源确认页面的任务模型与结构，不等于已获取登录后的完整界面或完成像素对齐。原型用虚构工作空间 Atlas、两个产品项目与 20 条初始任务呈现。参考 Linear 的信息架构和工作流程，视觉采用 Uagray 自身的环境、几何与反馈规则，不使用 Linear 标志、品牌字体或品牌素材。

目标是让组件承担成熟需求，暴露实际组合上的不足；不是测量大批量渲染的性能基准，也不通过增加装饰让页面看起来像产品。

## 组件如何承接需求

| 页面职责                 | 使用方式                                                                                  |
| ------------------------ | ----------------------------------------------------------------------------------------- |
| 工作空间、项目和任务导航 | Button、IconButton，宿主维护当前视图及 aria-current                                       |
| 侧栏环境                 | Surface 建立灰色环境，子控件读取对应 control 资源                                         |
| 项目概览 / 任务          | Tabs，进度从当前任务计算后交给 Progress                                                   |
| 搜索与属性筛选           | SearchField、Select，宿主组合筛选条件                                                     |
| 分组任务行               | 原生 section / ul / li、Checkbox、quiet Button、Badge；宿主负责列宽、长标题截断和窄宽换行 |
| 批量更新与删除           | SelectionBar、Button、ConfirmDialog                                                       |
| 新建任务                 | Dialog、Field、Input、Textarea、Select，原生 form 提交                                    |
| 任务详情                 | Drawer，复用任务字段；评论是独立表单                                                      |
| 浏览器存储失败           | Alert，仅在真实写入失败时显示                                                             |

仅增加宿主业务与排布，没有为了这题扩充库 API、添加图标资源或引入依赖。主任务行保留 36px 控件，以 6px 上下 inset 派生 48px 最低外高；低于桌面宽度时部分属性进入下一行。这里记录原型的实际选择，不把参考产品的未知尺寸写成结论。

## 已确认的能力差距

| 需求与来源                         | 本题的处理                               | 差距及其影响                                                                                                                |
| ---------------------------------- | ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Linear 文档中的标题 / 描述原位编辑 | Drawer 中统一编辑并显式保存              | 列表到详情再保存的操作路径更长。可先通过宿主编辑状态组合探索，不默认新增组件                                                |
| 任务描述的富文本内容               | 原生 Textarea 保留纯文本段落             | 缺少富文本、结构化任务清单和内嵌资源表达。属于大型编辑能力，本题不引入完整编辑器                                            |
| 任务属性的集中编辑                 | 现有 Select 显示完整下拉选项             | 当前导出没有可搜索的成员选择或通用 Popover / Menu；成员数量增加时，普通选项列表不足以承担快速定位。后续需真实用例再决定扩充 |
| 任务查看与编辑                     | 现有模态 Drawer                          | 当前库的 Drawer 调用 showModal，打开时背景不可操作；它不能直接承担同时浏览列表和详情的非模态分栏工作流                      |
| 创建任务时的草稿策略               | 取消后丢弃未保存属性；已发送评论独立保存 | 未实现 Linear 文档中的草稿保留、跨客户端草稿与描述历史                                                                      |
| 团队协作与持久化                   | 浏览器本地存储                           | 未实现身份、权限、多人同步、服务端请求与撤销历史；不能据此宣称已验证真实生产服务行为                                        |

密集列表中的状态图形、负责人头像、属性显示方式和一屏信息量仍需对照原产品界面确认。当前使用已有文本、Badge 和真实控件，不把视觉差距推断成必需新增组件。

## 本题发现的组合问题

跨项目移动的定向交互测试发现：在原生表单中，项目和里程碑选项同时变化时，现有 Select 的依赖字段回调了空值，覆盖了新项目的默认里程碑。当前宿主按项目 key 重建里程碑 Select，并只接受属于当前项目的值；跨项目移动测试验证最终保存值与项目一致。这里记录实际失败及宿主处理，未修改库组件；库层动态 options/value 与 Radix 原生表单桥接的契约仍值得单独检查。

## 验证与下一轮观察

定向测试覆盖任务创建校验、本地数据恢复、搜索与范围组合、批量更新范围、确认删除、评论与编辑共存、跨项目移动及里程碑一致性。设计检查登记任务行外高与上下 inset、工具行间距及换行契约。

仍待实际体验：宽屏与窄屏的信息密度、长标题可读性、Select 菜单与模态层交互、键盘焦点返回、侧栏展开后的阅读顺序、浅深表面关系，以及与原页面并排比较的操作成本。未使用浏览器验收，不将源码检查或 jsdom 测试当作光学、实际焦点或性能结论。

观察记录应包含具体任务、操作顺序、Uagray 表现、参考表现及证据，再区分宿主排布问题与组件能力缺口。本记录不授权一次性实施所有候选组件。
